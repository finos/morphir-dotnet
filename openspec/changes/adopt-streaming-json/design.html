Context

Observed: every command with machine output binds --json as a bool option and writes one report (CompileReport, ConfigurationReport, ExtensionListReport and others). Several detect the mode by scanning tokens for --json or --json=true, so a parse error can still be reported as JSON. Only compile has --json-lines: compact records with an event member (stageStarted, diagnostics, stageCompleted), flushed as they occur, ending with {"event":"completed","report":{…}}; combining the two flags exits 2. Morphir.Conformance's CLI adapter drives compile --json-lines. The parent's release qualification parses --json output. The parser is System.CommandLine 2.0.15.

Goals and non-goals

Goals: one flag, streaming by default, one report shape per command in both modes, no ambiguity with positional arguments.

Non-goals: new events for commands that have none today (beyond those add-model-convert adds for convert); changing any report's members; morphirup's --json; the MEP wire protocol.

Decisions

Worked example: morphir validate --input model.json --json before and after.

before: {"success":true,"exitCode":0,"input":"model.json",…}            (indented, one document)
after:  {"event":"completed","report":{"success":true,"exitCode":0,…}}   (one line)
        --json=document gives the "before" document

JSON-1. Stream by default, one option with a mode

A streaming command emits output as it happens, and tools such as claude -p --output-format stream-json, codex exec --json, cargo --message-format=json and go test -json put that stream on stdout. A single --json[=stream|document] option removes the pair of flags that exclude each other, and a bare --json streams. Alternatives: keep --json and --json-lines (two flags that cannot be set together; rejected); an --output-format option (replaces the established --json; rejected); stream only on convert (one flag with two meanings; rejected).

JSON-2. The record shape is compile's

Compile's records become the shape for every command:

  • each line is one compact UTF-8 object with an event member;
  • exactly one final completed record holds the full report under report;
  • the streamed diagnostics, taken together, equal the report's;
  • unknown events and members are ignored.

A command with no events writes only the completed line. That line is also a valid JSON document, so a whole-output parser can still read it (under report).

JSON-3. Values only with an equals sign

A probe of System.CommandLine 2.0.15 with an optional-value --json and a positional input gave:

ArgumentsPlain optional valueWith the bare-flag rewrite
--json model.jsonmode model.json, input missingmode stream, input model.json
--json=document model.jsonmode document, input model.jsonsame
--json document, no positionalmode documentunrecognized argument document
--json=bogusrefused: must be one of stream, document

So the CLI rewrites a bare --json to --json=stream before parsing. The rewrite runs after response-file expansion and never applies after --. The option then always carries its value inline. An unrecognized argument that names a mode gets the hint --json=<mode>. System.CommandLine also splits on :, so --json:document is accepted quietly but not documented. The same rule serves --compact[=<mode>] in add-model-convert. Alternative: allow --json document (breaks commands whose positional argument could be the word; rejected).

JSON-4. One writer, reports unchanged

A shared JSON output writer in Morphir.Tooling takes a command's events and its report and writes either form. It extends compile's existing JSON Lines writer rather than adding a second one, and it uses each command's existing source-generated JSON context for AOT. Report types do not change. Parse errors still pick the output mode by scanning tokens, now for --json, --json=stream and --json=document.

JSON-6. Parse errors of commands that take secrets stay redacted

config (show, set, unset), project migrate and workspace migrate already print fixed parse-error text, because their user docs promise diagnostics that do not echo raw, possibly secret, input (docs/content/docs/cli/config.md, troubleshooting). config set <key> <value> takes a secret as a positional value, and a parser message such as "Unrecognized command or argument '<token>'" would echo it. These commands therefore show only the parse messages that quote no user value besides an option name or a mode name: the --json=<mode> hint, the unknown-mode error, and unknown option names. Every message the cli-json-output scenarios require still shows. Alternative: show the full parser messages (would echo secrets; rejected).

JSON-5. Consumers move in the same step

In this repository:

  • CliAdapter.fs drives compile --json;
  • WorkerSessions.fs and WasmHost/Worker.fs read the new output;
  • JsonOutputAssertions and JsonCommandReport read either form, so no step parses stdout itself.

In finos/morphir, tools/cli-release.ts reads the completed line, landing with the pin move that carries this change. The in-flight establish-morphir-compatibility-kit change adopts the convention for mck run when it is next revised.

Risks and trade-offs

RiskMitigation
External scripts that parse --json as one document break.The project is pre-1.0 and the CHANGELOG states the change. --json=document restores the old output exactly, and the completed line of an eventless command still parses as one document.
The bare-flag rewrite mishandles --, response files or a value that happens to be a mode name.JsonOutput.feature and parser unit tests pin each case from the probe table.
--json=true in existing scripts stops working.It fails as an unknown mode that lists stream and document.
Streaming changes timing in tests that read stdout at exit.All black-box report checks go through JsonOutputAssertions, which reads the stream to the end.

Migration plan

  • Users who need one document add =document. compile --json-lines users drop -lines.
  • The parent's tools/cli-release.ts change lands with the pin move.
  • Rollback: revert the change. Reports are unchanged, so only the writer and parsing revert.

Open questions

  • When morphirup adopts the convention is decided in its own change.

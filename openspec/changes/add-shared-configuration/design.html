Context

See proposal.md for motivation. The existing F# Types.fs models only cache paths, and Merge.fs combines those options. CsToml parsing and ConfigResolver file access currently live in Morphir.Tooling, whose project references System.CommandLine and hosting. A new host must not depend on that CLI composition. The current cache-only resolver and its CI mode remain compatibility APIs.

Goals and non-goals

Keep canonical values, validation, profile resolution, and provenance pure and callable from C# and F#. Qualify format readers for .NET 10 trimming/AOT. This change resolves explicit supplied sources; automatic root discovery, IConfiguration projection, commands, and file editing belong to later campaigns.

Decisions

CORE-1. Add typed document contracts without replacing legacy records

Extend Morphir.Configuration with immutable discriminated unions/records for values, key segments, source identity, reports, diagnostics, and resolution inputs/results. Keep original MorphirConfig, ConfigLayer, ConfigResolution, and CiProfileMode entry points intact. Source inputs include original parsed fields and legacy normalization notes so migration can account for fields ignored by compatibility loading. Replacing the public cache records would break callers and erase migration evidence. Alternative considered: Replacing the cache-only records was rejected because it would break existing callers.

IO-1. Put parsers in a reusable adapter package

Create Morphir.Configuration.IO as a C# net10.0 library referencing the pure F# core and no CLI package. Readers map parser nodes into canonical typed values with source ranges; the core never reads files or environment variables. Reuse CsToml and YamlDotNet where they satisfy the selected profile, and qualify a complete JSON5 reader with pinned fixtures before accepting it. System.Text.Json with comments enabled is insufficient for unquoted keys and single-quoted strings. Parser/package versions and accepted edge cases are recorded with fixtures, not left as implicit library defaults. Alternative considered: Using the standard JSON configuration provider as the JSON5 reader was rejected because its syntax and typed-value model are insufficient.

MERGE-1. Resolve ordered source documents before host projection

Represent source role and format order explicitly. Fold typed trees with recursive maps, complete array replacement, shape replacement, and atomic secret-reference leaves. Track the winning origin while retaining ordered contributions for explain. Keep environment conversion and profile graph expansion in pure functions with explicit inputs. Resolve reserved controls before scope filtering so invalid activation sources cannot be hidden. A plain flattened key dictionary cannot enforce these rules. Alternative considered: Stacking flattened configuration providers was rejected because it cannot express whole-value replacement reliably.

PROF-1. Separate source selection from profile control authority

Keep root primary controls separate from ordinary settings. Apply includes, group expansion, last-occurrence ordering, bounds, and active profile names before loading eligible profile contents. Selected discovered base files keep control authority but ordinary values move once to the selected-file layer. Disabled profiles request no files and strip controls without interpretation. The discovery campaign will supply the root/member candidate inventory. Alternative considered: Allowing every higher-precedence layer to redefine profile activation was rejected because selected member/user values could silently redirect which files load.

TEST-1. Use upstream fixtures as a compatibility boundary

Record upstream revisions and fixture provenance, then compare typed values, errors, and winning origins. Add red-green behavioral slices for format equivalence, duplicate keys, legacy conflicts, merge shapes, shorter/empty arrays, environment conflicts, controls, and profile ordering. Keep existing cache/CI tests as regression coverage. Use explicit or source-generated APIs where reflection-based binding would threaten AOT. Alternative considered: Local examples alone were rejected as the compatibility oracle because they would not detect divergence from upstream hosts.

SCOPE-1. Filter complete ownership subtrees before inheritance

System/global sources cannot supply project or workspace subtrees to resolved project identity or topology. Member document inheritance excludes the root's entire project and workspace subtrees; the owning workspace context supplies output-root and membership context explicitly. Filtering only known name/member keys would leak future fields. Keep scope filters separate from profile-control validation so controls in forbidden sources still fail visibly. Alternative considered: Filtering only selected identity keys was rejected because future fields could leak from non-owning scopes.

Migration plan

Land the new core and readers with fixture tests and API documentation while existing commands keep their old resolver. Consumers adopt the new entry points explicitly in later campaigns. Rollback removes only the additive integration references; it does not rewrite project files.

Context

src/Morphir.SDK/Morphir.SDK.fsproj currently publishes Morphir.SDK, namespace Morphir.SDK and the corresponding runtime assembly. Generated F# refers to Morphir.SDK.Order and Basics.compare, and tests compile consumers against that assembly. A package ID is distinct from namespace and CLR type identity.

Goals and non-goals

Introduce the canonical F# package without changing existing source or binary identities, and fix covered SDK discrepancies. Exclude broad namespace modernization, a second runtime implementation and changes to IR formats or language support.

Decisions

LAND-1. Squash-aware landing and cleanup

Prefer squash merging for initiative and archival PRs unless PR instructions or repository settings select another method. Record the actual method, the distinct final submitted head SHA and the hosting service's recorded landed SHA. Verify that the exact PR is merged into main and its landed commit is reachable from refreshed main. Original worker commits need not remain ancestors of main after a squash. Successors use main with the landed SHA. Before cleanup, verify a clean owned worktree and HEAD matching its last submitted PR head with no extra local commits; git branch --merged is not landing proof for a squash.

FSPK-1. Preserve implementation identity while changing package ownership

Move or configure the implementation under the canonical Morphir.SDK.FSharp project/package while preserving the Morphir.SDK assembly name, namespaces and public runtime type identities. Retain existing assembly version/public-key policy. Publish the old Morphir.SDK ID as a pack-only compatibility dependency on the canonical package with no competing runtime asset. Do not use a same-named empty compatibility assembly or attempt to forward erased F# type aliases. Restore tests must install either and both packages.

FSPK-2. Update consumers without renaming generated symbols

Keep existing generated source spellings and generator entry points. Update package references, project references, example consumers and dependency documentation to the canonical F# package. Changes in src/Morphir.CodeGeneration.FSharp are limited to runtime integration needs; do not alter emission semantics to complete this migration. Existing output bytes should remain unchanged unless a separately reviewed documented correction requires otherwise.

FSPK-3. Correct bounded semantic gaps against external evidence

Implement the admitted F# test adapter and fix covered discrepancies. Dict.union's first-argument precedence is a known required correction. Preserve the original reference case and add a migration example showing the changed conflict result. Distinguish this compatibility-affecting bug fix from namespace/type-identity preservation; do not claim all observable behavior is unchanged.

FSPK-4. Test binary and package compatibility directly

Build a small consumer against the old packed runtime before migration, keep that input binary as test-time evidence with provenance, then execute it with the migrated runtime. Also compile unchanged generated source against each package combination. Project-reference tests alone cannot prove the compatibility-package asset graph. Restore into an isolated local feed and inspect assemblies for duplicate identities.

Thread ownership and dependency gates

Start implementation only after establish-dotnet-sdk-conformance has a verified PR merged into main. Start the worker checkout from main containing those merge commits, not an unmerged sibling branch.

Use the exact worker brief and coordination rules. Runtime and generation signatures come from the merged predecessor. Shared solution, package and PRD-index edits are integrated serially. The delivery lead owns only this change and its listed implementation areas. The auxiliary policy permits up to three auxiliaries per lead, sharing an initial global budget of three across at most two initiative leads. Start with one auxiliary and check CPU/memory headroom before expanding; only an explicit resource assessment and root-coordinator decision can increase the global budget. All agents use Codex gpt-6.1-sol with reasoningEffort high through T3 delegate_task, with capability discovery before each thread's first delegation and no recursive fan-out. Coordinate the one delivery-wide expensive-command slot, bound internal parallelism, and back off under resource pressure. Use disjoint writing ownership or orchestrator-created isolated worktrees with serial integration. The lead integrates results and required checks into one initiative PR; the root coordinator retains watching, landing, archive follow-up and cleanup, including auxiliary worktrees/helpers. Cancel unneeded tasks with task_cancel and follow event-driven completion without polling.

Completion requires a PR merged into main, verification of the merge commit, and removal of this initiative's clean worker worktree. An open PR or checked task list is not completion. Preserve uncommitted or unrelated work; do not remove the coordinator's checkout.

Verification

Use the scenarios in fsharp-sdk-packaging and the per-group checks in tasks.md. Follow red/green/refactor for production behavior. Test actual packaged/runtime/generated consumers where applicable; record exact toolchain versions and commands. Before contribution, run the repository-required full suite, coverage and formatting checks in addition to focused tests. No AI coauthor trailers.

Land only after the PR's required checks and reviews pass. Link created or pushed PRs through the orchestrator. If checks or reviews are pending, the root coordinator uses the PR-watch mechanism and resumes from its event; delegated children never watch PRs. Final evidence records the PR URL, head and merge SHAs, checks/reviews, confirmed main inclusion and workspace cleanup.

Risks and trade-offs

RiskMitigation
NuGet accepts both packages but resolves duplicate assetsUse one implementation owner and a dependency-only legacy package, then test the combined installation.
Correcting union changes a caller's resultRegression-test it and publish a targeted migration note; exclude unrelated semantic changes.
Changing assembly identity silently breaks old binariesCapture the old identity and run a precompiled consumer against the new runtime.

Migration plan

Pack the canonical runtime and legacy compatibility package together, then update repository consumers. Publish only after explicit release authorization. Rollback restores package references and runtime packaging together; retain the correction's migration note and do not remove the legacy package as part of this change.

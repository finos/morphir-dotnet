Context

The generation application already resolves exact targets, validates immutable backend options, loads typed JSON/Ion models, and publishes VFileTree through an ownership manifest. GenerationScenario statically registers the F# provider. The completed add-generate-command change contains newer behavior than the archived main F# spec.

Goals and non-goals

Add a thin first-party C# provider and CLI evidence while retaining the current application/publication contracts. Exclude config discovery, new publisher semantics, a build command, plugin installation and Roslyn integration.

Decisions

LAND-1. Squash-aware landing and cleanup

Prefer squash merging for initiative and archival PRs unless PR instructions or repository settings select another method. Record the actual method, the distinct final submitted head SHA and the hosting service's recorded landed SHA. Verify that the exact PR is merged into main and its landed commit is reachable from refreshed main. Original worker commits need not remain ancestors of main after a squash. Successors use main with the landed SHA. Before cleanup, verify a clean owned worktree and HEAD matching its last submitted PR head with no extra local commits; git branch --merged is not landing proof for a squash.

CSCLI-1. Adapt the library at the existing boundary

Implement CSharpGenerationBackend : IGenerationBackend and register it beside FSharpGenerationBackend in GenerationScenario. Declare only the exact model/distribution capabilities verified by the library. Adapt generated text sources to VFileTree and diagnostics to GenerationDiagnostic. Do not change the resolver to special-case C#, reopen retained input or load the generator dynamically.

CSCLI-2. Use a small validated option vocabulary

Accept numeric JSON language-version 14 or 15, default 14, and optional namespace as a validated C# namespace string. Reuse core validation so direct and CLI callers agree. Repeated options retain the existing last-wins rule. Wrong JSON kinds, preview/latest aliases, unsupported numbers, invalid names and unknown keys are invocation errors. Namespace selection affects generated names only through the core's deterministic naming contract. Do not add a second top-level language flag or advertise unavailable optimization options.

CSCLI-3. Keep compiler and publication work with the caller

The backend request has no output directory; successful sources are published through GenerationPublisher. JSON stdout, stderr diagnostics and exit codes retain existing behavior. The CLI emits source without installing or invoking a compiler. Tests compile the resulting files separately under the matching toolchain. Static registration, source-generated report serialization and reflection-free execution preserve trimming/AOT.

CSCLI-4. Add a cohesive C# capability without rewriting in-flight history

cli-model-generation is currently defined in add-generate-command, which is complete but not archived here. This change adds cli-csharp-generation alongside it and references the existing contracts. Do not modify or archive another change, or rewrite main specs to pretend that delta is already merged. During integration, verify the prerequisite CLI implementation commit and preserve its entire published contract.

Thread ownership and dependency gates

Start implementation only after add-csharp-code-generation has a verified PR merged into main. Start the worker checkout from main containing those merge commits, not an unmerged sibling branch.

Use the exact worker brief and coordination rules. Runtime and generation signatures come from the merged predecessor. Shared solution, package and PRD-index edits are integrated serially. The delivery lead owns only this change and its listed implementation areas. The auxiliary policy permits up to three auxiliaries per lead, sharing an initial global budget of three across at most two initiative leads. Start with one auxiliary and check CPU/memory headroom before expanding; only an explicit resource assessment and root-coordinator decision can increase the global budget. All agents use Codex gpt-6.1-sol with reasoningEffort high through T3 delegate_task, with capability discovery before each thread's first delegation and no recursive fan-out. Coordinate the one delivery-wide expensive-command slot, bound internal parallelism, and back off under resource pressure. Use disjoint writing ownership or orchestrator-created isolated worktrees with serial integration. The lead integrates results and required checks into one initiative PR; the root coordinator retains watching, landing, archive follow-up and cleanup, including auxiliary worktrees/helpers. Cancel unneeded tasks with task_cancel and follow event-driven completion without polling.

Completion requires a PR merged into main, verification of the merge commit, and removal of this initiative's clean worker worktree. An open PR or checked task list is not completion. Preserve uncommitted or unrelated work; do not remove the coordinator's checkout.

Verification

Use the scenarios in cli-csharp-generation and the per-group checks in tasks.md. Follow red/green/refactor for production behavior. Test actual packaged/runtime/generated consumers where applicable; record exact toolchain versions and commands. Before contribution, run the repository-required full suite, coverage and formatting checks in addition to focused tests. No AI coauthor trailers.

Land only after the PR's required checks and reviews pass. Link created or pushed PRs through the orchestrator. If checks or reviews are pending, the root coordinator uses the PR-watch mechanism and resumes from its event; delegated children never watch PRs. Final evidence records the PR URL, head and merge SHAs, checks/reviews, confirmed main inclusion and workspace cleanup.

Migration plan

Add one provider registration, a project reference and additive docs. Keep existing F# invocations and JSON schema behavior. Rollback removes the C# registration and dependency; do not remove generated user files or change ownership-manifest semantics.

CSCLI-5. Add source-compatible namespace naming

The integration lease preserves GenerationOptions and the three-argument Generate API. NamespaceOverride has private construction, an immutable Value, and TryCreate returning a typed diagnostic. A four-argument overload and the existing overload call one implementation. The naming context is immutable and local to the request. It replaces the input Library package's emitted namespace across declarations, record/alias/generic type rendering, constructors and top-level value references. Original typed models, source paths, SDK/System names and the equality protocol remain unchanged.

The literal-name boundary admits dotted BMP identifiers in Unicode Normalization Form C, with escaped reserved words and Unicode identifier categories. It refuses source escape syntax and surrogate characters rather than interpreting them. Null parsing and an explicit null override return invalid-namespace at $options/namespace; caller cancellation retains precedence. Compiled edge cases and concurrent requests verify admission and isolation.

Reporting retains the generic command contract. JSON stdout contains one report including structured diagnostics and no plain-text logs. Human diagnostics and emitted log text use stderr; JSON failures need not duplicate report diagnostics as stderr text.

Native diagnostic formatting

Actual native execution exposed eager F# structural reflection in diagnostic formatting. Five diagnostic-only sites in TypeEmission and ValueLowering now use small explicit name, path and exhaustive shape formatters with cancellation checks. Diagnostic text and the module-validation location spelling intentionally change; rule IDs, public APIs, generated source bytes and paths remain unchanged.

The owned publish commands retain visible warnings with TreatWarningsAsErrors=false and TrimmerSingleWarn=false, matching the predecessor acceptance policy. No warning suppression, reflection roots or serializer changes are added. Actual trimmed/native generation, structured semantic refusals and separately compiled business consumers establish the executed generation path. They do not establish AOT safety for unrelated commands. The validation record retains every failed attempt and classifies inherited warnings by origin and repeats.

Context

See proposal.md for motivation. MorphirCliBuilder and ICommandProvider already support additive command scenarios. The current CLI has no config family, and default hosting loads unrelated host settings. Shared configuration and discovery supply the resolved canonical result before this campaign. IConfiguration uses flattened strings and case-insensitive keys, so it cannot be the canonical Morphir model.

Goals and non-goals

Expose shared typed queries and familiar .NET consumption with thin CLI formatting. Keep writes, migrations, reload/watch services, and changes to unrelated command behavior outside this campaign.

Decisions

QUERY-1. Put queries and key paths in the pure shared library

Define immutable query results for get/list/show/path/explain over the resolved result and source reports. Use segmented, case-sensitive paths with dot separators and JSON-escaped double-quoted literal segments; arrays remain whole query values. Scope filtering chooses explicit source groups before query evaluation, never fills a scoped miss from effective defaults. This grammar is reused by editing. Alternative considered: Querying only IConfiguration was rejected because it loses typed values, case-sensitive paths, and source history.

DOT-1. Project one resolved result into IConfiguration

Create Morphir.Configuration.Microsoft as an optional C# adapter referencing the core and reusable loading boundary. AddMorphirConfiguration accepts explicit options or an already resolved result and registers a single projected provider. Keep canonical document/provenance accessible separately. Do not add raw JSON/YAML/TOML providers to ConfigurationBuilder because their indexed merge would leave stale array elements. Validate empty-array binding against .NET 10's supported explicit/source-generated options path. Alternative considered: Registering one raw provider per format was rejected because indexed arrays can retain lower-source elements.

KEY-1. Reject .NET projection collisions

Before projection, detect canonical paths that collide after case folding or colon-based hierarchy encoding. Return typed diagnostics with the original paths; never silently pick a key. The canonical result remains usable even if optional projection fails. Escaping into an undocumented flattened format would confuse standard .NET consumers. Alternative considered: Inventing an escaping convention for standard .NET keys was rejected because ordinary binders would not understand it.

CLI-1. Register config reads through one additive scenario

Add a configuration scenario/provider that registers services without performing I/O. Parse profile/target/key-path usage before discovery; help must not build resolution services or read configuration. Invoke shared query services and format source-generated DTOs through existing stdout helpers. Do not change default host logging or claim existing commands consume settings they have not adopted. Alternative considered: Loading configuration during command construction was rejected because help and invalid usage must avoid I/O.

OUT-1. Use one redaction and result contract across hosts

Redact sensitive values before human/JSON presentation, retain safe key/scope/origin metadata, and never resolve references. Use ordered result entries and source reports. JSON output is one typed result with diagnostics; stderr carries human diagnostics. Distinguish missing values from empty values and map success/missing/load failures to 0/1/2. Alternative considered: Independent redaction in each formatter was rejected because host and CLI output could disagree.

Implementation detail confirmed during delivery: nonfinite numbers use {"$number":"NaN"}, Infinity or -Infinity tags. The report's separate valueTypes array identifies each actual number by JSON Pointer, kind=number and encoding=nonfinite. Ordinary tag-shaped objects have no numeric discriminator. Finite values retain JSON types; temporal strings retain canonical kind metadata. Redaction precedes encoding. The linked-source serializer host qualifies managed, trimmed and native behavior without reflection serialization.

The additive ResolutionDetails keeps canonical and ownership-filtered layers for pure inspection while existing DocumentResolution APIs stay compatible. Selected sources retain discovered scope identity. The Microsoft provider masks earlier related replacement subtrees, rejects case/separator/empty-segment collisions, and retains canonical metadata. Help alone disables host defaults that would read appsettings; ordinary invocation defaults remain compatible.

Migration plan

Land only after shared resolution and discovery are available on main. Add the new CLI scenario and optional adapter with documented opt-in examples. Existing IR and management commands retain their current configuration behavior. Rollback removes additive registrations; no project file is edited.

Context

The proposal introduces knowledge libraries and a bundle validation command. The .NET CLI already composes commands through Morphir.Tooling, and Morphir.Files exposes virtual files and Microsoft file-provider adapters. Existing library releases use a dependency-ordered package inventory in the Nuke build.

In the example below, a reviewer opens metrics/net-revenue.md in an OKF bundle, selects two non-adjacent passages from a saved revision, and links them to an approved RDF statement about the definition of net revenue. CI validates the bundle, and another .NET consumer reads the RDF dataset from N-Quads.

Goals and scope

Keep parsing, selection and graph addressing usable by libraries and give the CLI the same conformance results. A package consumer chooses OKF, RDF, or the shared knowledge contracts according to the data it works with.

Review applications own persistence, presentation and decisions about moving annotations across revisions. Interchange adapters can project these contracts to Web Annotation, and RDF engines can use the dataset API for storage, query or inference. Those integrations have their own delivery scope.

OKF-1. One source and document root for both trees

OkfDocument owns one immutable source snapshot. The CST contains the YAML frontmatter envelope, YAML syntax, and Markdown syntax. The AST exposes the YAML value tree and Markdown blocks and inlines under a single root. Once the bundle path and OKF version are known, typed views interpret concept, index and log metadata. In particular, OKF field decoding must leave unknown keys inspectable and report invalid known values where they occur.

type Frontmatter =
    | Absent
    | Parsed of YamlNode
    | Invalid of SourceSpan

type OkfDocumentAst =
    { Frontmatter: Frontmatter
      Body: MarkdownNode }

type OkfDocument =
    member Source: OkfSource
    member Syntax: SyntaxNode
    member Ast: OkfDocumentAst

type OkfParseResult =
    | ParsedDocument of OkfDocument * Diagnostic list
    | UnreadableSource of Diagnostic

For the first implementation, recognize the exact OKF fence lines at the document boundary, use YamlDotNet tokens and parser events for YAML, and enable Markdig precise positions, trivia, GFM tables and footnotes. Adapt both libraries into Morphir-owned trees and translate their positions into the original document coordinate system. The delimiter recognizer owns the OKF rule that the closing fence is exactly ---.

The disposable proof on .NET 10 and 11 used Markdig 1.6.0 and the repository's YamlDotNet 16.3.0. A depth-first walk of 58 leaves reproduced all 278 original bytes. A block-close callback captured an unused footnote, and the adapter recovered a table alignment row from the source. The proof also retained the body after a fenced YAML error and handled a header-only table at EOF. Full CST coverage still requires structured syntax beyond those fixtures, including Markdown reference definitions, nested constructs, YAML collections and unresolved citation spellings. Unexplained spans are evidence to improve the projection, with explicit error nodes for malformed regions. See the document contract and Markdig footnote processing.

OKF-2. Cursors traverse immutable trees

Both trees expose the same typed cursor operations, including parent, first child, adjacent siblings and a source-ordered pre-order walk bounded by the starting subtree. An enter callback returns continue, skip children, or stop. A shared cursor implementation uses each tree's child and span accessors. The visitor sees one document snapshot and follows structural edges; bundle links resolve through explicit lookup. This keeps visits finite when two concepts link to each other.

type VisitControl = Continue | SkipChildren | Stop

val syntax: OkfDocument -> Cursor<SyntaxNode>
val ast: OkfDocument -> Cursor<AstNode>
val walk: (Cursor<'Node> -> VisitControl) -> Cursor<'Node> -> unit

OKF-3. Load and validate a knowledge bundle

Load KnowledgeBundle from a virtual file tree or provider. The CLI opens a physical root using contained path resolution. Retain unreadable document results per member and index the paths of documents and assets so one malformed concept does not hide other findings. Concept IDs are their bundle-relative Markdown paths with the suffix removed. The resolver distinguishes relative and root-relative OKF paths and treats external targets as such. The physical loader enforces containment before opening a file and the lookup path never turns an external reference into a file or network read.

Use --okf-version when supplied, then the supported version declared by the root index, with v0.3 as the undeclared default. An unknown declaration yields best-effort findings and an unverified conformance result. Version-specific rules decide how to treat ordinary Markdown and older path conventions. Use --policy morphir to enforce the repository's root index, local link, index-description, and source-citation checks. A link can fail Morphir policy while the bundle remains conformant to OKF. The --json route writes one structured report to stdout using the existing CLI output conventions. Human output and JSON derive from the same sorted findings.

Conformance references the v0.2 specification and the v0.3 specification. See the bundle validation contract.

ANN-1. Attach selections to immutable revisions

The review application binds the parsed text to a document version. DocumentId wraps a validated absolute Iri, independent of bundle path. Keep the IRI spelling and use ordinal equality for identity, as for RDF. A source provider issues a nonempty RevisionId scoped to the document, such as a Git commit or persisted editor snapshot key. The pair must resolve to the same text whenever it is reopened. An interchange adapter can assign an IRI to the pair when it needs a public version resource. See RDF IRI equality.

/// A zero-based position in UTF-16 code units.
[<Struct; IsReadOnly>]
type TextOffset = private TextOffset of int

[<Struct; IsReadOnly>]
type SourceSpan = private SourceSpan of TextOffset * TextOffset

type DocumentVersion =
    { Document: DocumentId
      Revision: RevisionId }

type TextSelection =
    member Version: DocumentVersion
    member Ranges: ImmutableArray<SourceSpan>

type Annotation<'Target, 'Body> =
    { Id: AnnotationId
      Target: 'Target
      Body: 'Body
      Provenance: AnnotationProvenance }

type KnowledgeLink<'Source, 'Target> =
    { Id: LinkId
      Source: 'Source
      Predicate: Iri
      Target: 'Target }

Use smart constructors to reject negative offsets and reversed endpoints. Both coordinates use the same offset type, and the zero-initialized span is the valid empty range at the start. A source validates the upper bound. Use value options for optional spans. A selection's constructor additionally rejects empty and overlapping ranges and sorts valid ranges into source order. Each selection represents all of its ranges together. The application can supply a review body or dictionary-concept IRI and can independently attach links to a text selection, graph or statement. An annotation is separate data and preserves the source version and bytes.

Moving a review to a later version is an explicit application decision. If an adapter adds quote-based reanchoring, it must distinguish a unique match, ambiguous matches and missing text. A Web Annotation adapter must convert UTF-16 ranges to code-point offsets in the exported representation and preserve the group of disjoint ranges. See the annotation contract and Web Annotation grouping guidance.

RDF-1. A graph and a statement have different addresses

The two passages support the triple about net revenue in the approved graph. The same triple can also be in the draft graph. An RDF dataset retains the default graph and a map of named graphs, including empty ones. A versioned dataset reference identifies the immutable dataset snapshot. A graph target adds its graph location, and a statement target adds its quad. Separate authored claims can share the same quad and carry different identities and provenance.

type GraphName =
    | IriName of Iri
    | BlankNodeName of BlankNodeId

type GraphLocation =
    | DefaultGraph
    | NamedGraph of GraphName

type Quad =
    { Subject: RdfSubject
      Predicate: Iri
      Object: RdfObject
      Graph: GraphLocation }

type GraphRef =
    { Dataset: DatasetVersion
      Graph: GraphLocation }

type StatementRef =
    { Dataset: DatasetVersion
      Quad: Quad }

Expose Quad.toTriple and Quad.ofTriple for graph-level callers. Typed subject, predicate and object terms enforce valid RDF positions. Literal values preserve their RDF lexical spelling and datatype or language tag. Blank-node identities are local to the input import, with one label map across all graphs in a single N-Quads document. The same lexical label in another import allocates a different identity. The dataset projection keeps graph membership and set semantics independent of serialization labels.

RDF-2. N-Quads reads and writes the RDF 1.1 model

Use a focused UTF-8 N-Quads codec in the RDF library and exercise the W3C positive and negative parser cases. The optional fourth term selects a named graph, with the default graph used when it is absent. Import and export must preserve dataset structure up to blank-node renaming. The writer checks for empty named graphs before it writes. The caller can explicitly allow their omission and receives the list of omitted graphs.

Use RDF 1.1 to define the public interchange behavior. An adapter for RDF 1.2 triple terms and reifiers can map the authored-statement identity separately when that interchange profile is added. See the dataset contract, RDF 1.1 datasets and N-Quads.

Release plan

Use the repository library target-framework property for both frameworks and register the three projects in LibraryPackages before dependent packages. PackLibs builds and validates the package inventory. Use a local feed to verify F# and C# consumers and dependency closure before release. The existing deployment.yml workflow calls PublishLibs after testing and obtaining a short-lived NuGet credential. The approved release publishes the libraries in dependency order and verifies each version through NuGet.org. See the NuGet contract, implementation tasks and NuGet policy scopes.

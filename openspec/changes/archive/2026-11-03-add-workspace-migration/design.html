Context

See proposal.md for motivation. A selected repository directory can contain classic projects before any declared Morphir workspace exists. The prior project campaign provides independently verified plans and the edit campaign supplies staging/preconditions. Existing generated-output publication does not promise multi-file rollback or crash atomicity.

Goals and non-goals

Coordinate a bounded inventory and one reviewed workspace adoption plan with per-project reuse. Preserve existing ownership/settings and disclose incomplete recovery. Do not discover ancestors, absorb nested independent workspaces, run compilers, delete classic files, or promise one atomic operation across multiple filesystems.

Decisions

INV-1. Inventory the selected root before project discovery

workspace migrate takes the supplied directory or current directory as its operation boundary even when no primary exists. Walk deterministically, skip links and version-control/dependency/build outputs, and stop at nested workspace declarations. Root-relative repeated include/exclude filters refine candidates while existing exclusions remain effective. Report exclusions and boundaries so a preview explains omissions. Alternative considered: Requiring an existing declared workspace was rejected because initial adoption must work before one exists.

PLAN-1. Compose project plans with explicit membership edits

Call the single-project planner for every selected classic member and retain already migrated members as unchanged. Build explicit root-relative member paths, preserve existing membership/default selection/settings, and distinguish root project from virtual workspace. Duplicate names remain distinct paths with diagnostics. No separate batch mapping implementation can weaken loss accounting. Alternative considered: A separate batch converter was rejected because its mappings and loss checks could drift from project migration.

VER-1. Verify the aggregate candidate before any replacement

Build the complete proposed workspace context and compare each classic-to-TOML conversion within that common context, excluding converted classic sources and ambient overlays under project-equivalence rules. Separately report intended adoption effects: workspace topology, shared output root, membership, and default selection. Verify that each intended change matches the approved plan and that source paths and all other values remain equivalent. A new shared output root is an adoption effect, not a conversion failure. Rerun resulting discovery and selection before any write; do not move generated files. Alternative considered: Comparing standalone and adopted output roots as equal was rejected because workspace creation intentionally changes ownership and topology.

TXN-1. Journal a coordinated batch without claiming crash atomicity

Extend the shared IO transaction adapter with deterministic lock acquisition, full preflight, same-filesystem staging for each target, and a durable journal recording each replacement and backup. Recheck source/target/listing evidence before entering commit. Attempt rollback when a later replacement fails; report restored and unresolved paths. One-file atomic replacement does not make the entire batch crash-atomic. Alternative considered: Claiming one cross-file atomic rename was rejected because filesystems do not provide that guarantee for this batch.

REC-1. Treat unresolved recovery as unfinished work

Overlapping writers inspect the shared transaction state and refuse to proceed while recovery is required. Keep recoverable backups and an identifiable journal after incomplete rollback or interruption. Remove only owned staging/recovery artifacts on success or proven complete rollback. A valid equivalent repeat is a no-op and must not change timestamps. Alternative considered: Deleting journals after an uncertain failure was rejected because it would destroy recovery evidence.

CLI-1. Present the whole adoption through a thin workspace command

Expose workspace migrate with dry-run, JSON, and include/exclude controls. Return a structured aggregate report for CLI or embedded hosts: inventory, boundaries, project plans, membership edits, blockers, verification, and recovery state. Exit 0 only for applicable previews, success, or valid-workspace no-ops; blocked or uncertain outcomes exit 2. Alternative considered: Executing project migrations sequentially from a CLI loop was rejected because that would lose aggregate preflight and non-CLI reuse.

Migration plan

Land after the single-project migrator is verified on main. Qualify no-workspace adoption, existing-workspace additions, blocked-member all-or-nothing preflight, injected commit/rollback failures, interruption recovery, and timestamp-preserving repeats. The rollout changes files only after an explicit workspace migration request. Rollback uses the recorded transaction or a reviewed follow-up change; it never deletes classic manifests or discards unresolved recovery state.

Campaign completion

This campaign is complete only after one reviewable PR has landed on main and the campaign-owned worktree and local/remote branches have been removed. Passing tests or opening a PR alone is not completion.

  1. Start from current main after the prerequisite campaigns have landed. Use one owned branch and worktree for this campaign, and record their identities.
  2. Complete behavior, tests, documentation, relevant formatter/AOT checks, and the repository's required checks. Update the PR description and evidence for its final head; address verified review findings.
  3. When implementation is complete, sync/archive this OpenSpec change in the campaign PR, preserve the reviewable design and specs, and validate the resulting planning state.
  4. Merge through the repository's normal review and required-check policy. No force push, admin bypass, deployment, or release is implied by this plan.
  5. Verify authoritative PR merged state, capture its landed commit SHA, and verify the change is present on main. After confirming the worktree has no unique uncommitted/unmerged work, remove that campaign's worktree and local/remote branches through the owning workspace/forge tools. Check they are absent. Do not force removal or prune unrelated artifacts.
  6. Report the PR URL, landed SHA, check/review evidence, archive/spec-sync outcome, and cleanup results. Preserve unrelated work and unresolved recovery journals; if cleanup or recovery is blocked, report it and keep the campaign unfinished.

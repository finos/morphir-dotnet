Context

The current SDK is F# based. C# consumers need independent public types. System.Collections.Immutable gives persistent storage, but its collection equality and default comparers do not establish Morphir value semantics. This change starts only after the conformance contract is integrated.

Goals and non-goals

Ship the bounded, immutable C# SDK and prove it as a package. Exclude compiler/CLI dependencies, complete SDK coverage, a separate runtime for each C# version and a dependency on the F# runtime.

Decisions

LAND-1. Squash-aware landing and cleanup

Prefer squash merging for initiative and archival PRs unless PR instructions or repository settings select another method. Record the actual method, the distinct final submitted head SHA and the hosting service's recorded landed SHA. Verify that the exact PR is merged into main and its landed commit is reachable from refreshed main. Original worker commits need not remain ancestors of main after a squash. Successors use main with the landed SHA. Before cleanup, verify a clean owned worktree and HEAD matching its last submitted PR head with no extra local commits; git branch --merged is not landing proof for a squash.

CSRT-1. Use one C# runtime and explicit payload meanings

Use namespace and package Morphir.SDK.CSharp. The initial public vocabulary is Maybe<T>, Result<TError,TValue>, Unit, Order and the admitted operations. The Result parameter order follows Morphir; F# adapters account for the F# success/error reversal. Constructors and combinators preserve that mapping. Use the stable C# baseline and the conformance contract's scalar representations. A higher generated language version consumes the same package; native C# 15 unions are not required to use this SDK.

CSRT-2. Use immutable storage and structural SDK collection values

Back SDK List<T>, Dict<TKey,TValue> and Set<T> value wrappers with ImmutableList<T>, ImmutableSortedDictionary<TKey,TValue> and ImmutableSortedSet<T>. These thin wrappers supply the structural equality, hashing and admitted comparers that raw BCL collection Equals does not supply. Do not rebuild persistent trees or wrap every BCL scalar. Expose immutable observations/enumeration and operations; keep builders and mutable buffers private. Generated records can then compose SDK value semantics consistently.

CSRT-3. Preserve comparator and hash contracts

Factories choose the admitted total Morphir comparer for supported key types, including strings and supported compound keys. Never use culture-sensitive default comparison as a substitute. Dict/Set updates retain that comparer. Hashing matches structural equality and does not depend on insertion history. Reject unsupported comparison/equality domains explicitly as required by the frozen baseline. Immutability of the container does not make arbitrary caller-supplied mutable T values immutable; generated payloads and supported SDK data use immutable types.

CSRT-4. Keep runtime and compiler-host requirements separate

Initially target the repository's net10.0 baseline for runtime consumers; keep dependencies to the BCL and System.Collections.Immutable. No references to Models, Tooling, Ion, Roslyn or FSharp.Core. Any future broader runtime targeting is a measured addition. The runtime runs in the generated application's process; it need not be loaded by the future generator host.

CSRT-5. Prove public behavior with the shared corpus

The C# adapter consumes the predecessor's cases without deriving expected values from C# code. Add public consumer compilation, immutability and nested equality/hash tests alongside each implemented operation. Pack and restore from an isolated local feed, compile representative consumers under pinned stable and RC toolchains and publish a small trimmed/AOT consumer. Do not add a second fixture or compiler harness where the repository already has reusable behavior inputs.

Thread ownership and dependency gates

Start implementation only after establish-dotnet-sdk-conformance has a verified PR merged into main. Start the worker checkout from main containing those merge commits, not an unmerged sibling branch.

Use the exact worker brief and coordination rules. Runtime and generation signatures come from the merged predecessor. Shared solution, package and PRD-index edits are integrated serially. The delivery lead owns only this change and its listed implementation areas. The auxiliary policy permits up to three auxiliaries per lead, sharing an initial global budget of three across at most two initiative leads. Start with one auxiliary and check CPU/memory headroom before expanding; only an explicit resource assessment and root-coordinator decision can increase the global budget. All agents use Codex gpt-6.1-sol with reasoningEffort high through T3 delegate_task, with capability discovery before each thread's first delegation and no recursive fan-out. Coordinate the one delivery-wide expensive-command slot, bound internal parallelism, and back off under resource pressure. Use disjoint writing ownership or orchestrator-created isolated worktrees with serial integration. The lead integrates results and required checks into one initiative PR; the root coordinator retains watching, landing, archive follow-up and cleanup, including auxiliary worktrees/helpers. Cancel unneeded tasks with task_cancel and follow event-driven completion without polling.

Completion requires a PR merged into main, verification of the merge commit, and removal of this initiative's clean worker worktree. An open PR or checked task list is not completion. Preserve uncommitted or unrelated work; do not remove the coordinator's checkout.

Verification

Use the scenarios in csharp-sdk-runtime and the per-group checks in tasks.md. Follow red/green/refactor for production behavior. Test actual packaged/runtime/generated consumers where applicable; record exact toolchain versions and commands. Before contribution, run the repository-required full suite, coverage and formatting checks in addition to focused tests. No AI coauthor trailers.

Land only after the PR's required checks and reviews pass. Link created or pushed PRs through the orchestrator. If checks or reviews are pending, the root coordinator uses the PR-watch mechanism and resumes from its event; delegated children never watch PRs. Final evidence records the PR URL, head and merge SHAs, checks/reviews, confirmed main inclusion and workspace cleanup.

Risks and trade-offs

RiskMitigation
Thin wrappers add API typesRestrict them to SDK collections where value semantics require them; use BCL immutable storage internally.
Accidental F# dependency through shared projectsAssert the packed dependency closure in consumer tests.
Collection ordering differs across culturesUse explicit admitted comparers and culture-varied tests.

Migration plan

Introduce the new package additively. Existing Morphir.SDK users are unaffected. Rollback removes only the new C# package and its consumers; never rename or repurpose the legacy package in this change.

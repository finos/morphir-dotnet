Context

Observed today. src/Morphir.CodeGeneration.CSharp writes C# text with String.concat and StringBuilder and has no Roslyn dependency. It refuses LetRecursion (rule local-recursion). No product code reads C#. The only source generator is a test adapter. morphir generate runs no analyzer and no pass. Morphir.Models has the classic IR (versions 1 to 3.1) and the V4 IR, and V4 value attributes already have Source, InferredType and Extensions. The F# frontend (src/Morphir.Frontend.FSharp) is the precedent for fixed references, the admission catalog and host-supplied documents. Extensions are registered in src/Morphir.Extensions with IModelAnalyzer as the only in-process pass contract.

Measured on 2026-11-15 (spike report, macOS arm64, SDK 11.0.100, Roslyn 5.12.0):

  • Parse, bind, analyzers, data-flow and control-flow analysis and SyntaxFactory output run under Native AOT with the same output as JIT. The Workspaces layer does not run under Native AOT and is not used.
  • The Native AOT morphir grows from 47.9 MB to 76.0 MB. The publish gate passes with one more IL2104.
  • closed record and union give exhaustive switch expressions (CS8509 on a missing arm), and compile for net8.0, netstandard2.0 and net10.0 with five internal polyfill types.
  • A source generator with an F# core (Morphir.Models and the backend built for netstandard2.0) loads in SDK 10.0.100, 10.0.403 and 11.0.100. A generator compiled against Roslyn 5.12 does not load in SDK 10.0.403.

Constraints. The repository rules apply: parsed domain types, immutable models, TDD, stderr for logs, Gherkin conformance corpora with the closed step vocabulary, and the AOT publish gate in src/Morphir/Morphir.csproj. Node identity follows the draft node address contract of finos/morphir, which morphir-dotnet does not own.

Goals and non-goals

Goals: one package for the frontend, the target-side middle end and the backend; the same refusal in the IDE, in dotnet build and in morphir compile; a round trip from C# to IR and back with the same IR; generation in a user build with no CLI; C# as a built-in of the Native AOT morphir.

Non-goals: decorators, the IR document tree, incremental compile and the node address resolver (the design keeps constraints for them); a port of Optimizer.fs or TypeValidator to the current IR; loop lowering for F#; Roslyn code fixes inside any host.

Decisions

The journey of one model through the pipeline. The worked example is the Acme.Trading model: a closed record Order with two cases, a Notional function, and a Total method with a foreach.

PKG-1. One package, four assemblies (PRD D1, D5, D10)

Morphir.Lang.CSharp is one NuGet package. Its assemblies: an F# main assembly (lowering, passes, backend, pipeline function); Analyzers (C#, netstandard2.0, Roslyn only: admission rules and the loop recognizer); CodeFixes (C#, loaded only by an IDE, uses Workspaces); Attributes (C#, netstandard2.0). The generator is a fifth project in the package. The analyzers are C# because Roslyn loads them in compilers and IDEs that cannot host an F# assembly with a large dependency set. Alternatives: one F# assembly (an IDE would then load FSharp.Core for every rule), or separate packages (rejected by the product owner on 2026-11-15).

PIPE-1. One pipeline function with three callers (PRD D2, D10)

Upgrade, target-side passes and backend are one pure function in a library with a small dependency set. The CLI, the MSBuild target and the source generator call it, so the engine, the contracts, the upgrade steps and the C# passes also build for netstandard2.0. The spike built Morphir.Models and the old backend for netstandard2.0 with one polyfill file and one open line in ten files. Production code does not copy sources: the shared libraries multi-target netstandard2.0 and the repository TFMs, with the polyfill file compiled only for netstandard2.0. Alternative: a copy per host (rejected: three implementations of one rule).

FRT-1. Frontend on Roslyn with fixed inputs (PRD D1, D7, D9, D12)

The frontend gets documents from the host, creates a CSharpCompilation with language version 15 and a fixed reference set (framework reference assemblies and Morphir.SDK.CSharp, embedded in the package because the Native AOT host has no runtime assembly files), and runs three stages: compile errors stop with csharp.compiler diagnostics; admission runs the analyzer rules in process; lowering turns symbols and IOperation trees into the current IR with a source range on each node. It never calls Emit or Assembly.Load, and never uses ToString() of a Roslyn enum for IR or a code, because JIT and Native AOT can give different names. Types in a namespace are the module of the namespace, and a static class is a module below it; a module below a static class is a nested static class. For the worked example, Order, Market and Limit are in module acme.trading, and Notional is a value of acme.trading.pricing.

ADM-1. Admission rules are analyzers (PRD D5)

Each refusal is a DiagnosticAnalyzer rule with a short id (MORPHIR1001) and the tag NotConfigurable, so #pragma, .editorconfig and NoWarn cannot hide it; the rule MORPHIR1008 refuses a SuppressMessage attribute that names a rule, and morphir compile refuses a hidden construct all the same. The rule IRI is in HelpLinkUri. The package puts the assembly in analyzers/dotnet/cs. A model project is marked with [assembly: MorphirModel] or an MSBuild property, and the analyzer is silent elsewhere. To keep the IDE and morphir compile equal, the package sets the compile options of a model project in a props file, and a rule refuses a symbol from an assembly outside the fixed reference set. Failure path: a project that uses an unknown NuGet type gets one error at the use, in the IDE and in the compile.

UPG-1. Upgrade is previous-to-latest and emits lineage (PRD D4)

An IIrUpgrade step reads one format version and writes the next. The host joins steps up to the current IR; a new IR adds one step and moves "current". No contract names a version. A step returns Checked of the model and the application list, because a model can hold a node that the next version cannot express. A step that moves a node emits a record with the id of the step, the address before (pinned to the input) and the address after. Upstream has no conversion of addresses between formats, so this list is the conversion; the upstream proposals #1178 and #1179 would fit it. morphir generate upgrades only when the backend claims the current IR only, and the F# backend keeps reading classic models. Alternative: re-resolve old paths in the new model (rejected: it cannot tell the same node from the same position, for example after an unreachable case is removed).

MID-1. Passes are registry entries with compiled rules (PRD D2, D3)

A pass is an extension of type transform beside IModelAnalyzer, claiming a stage: after a frontend, or before the backend of one target id. A rewrite rule is compiled code with an IRI id, a title, a before/after example that the test suite runs, and the IR features it removes and adds. The engine applies a rule set bottom-up, top-down or as a fixed point with a round limit, processes one module at a time, and reads other modules through a package view that records each lookup. It records each application (rule, address before pinned to the pipeline input, address after, source location). A second pass on a replacement keeps the first origin. A replacement keeps the attributes of the node it replaces, so a later diagnostic points to the user's source. The host checks that every IR feature that a backend cannot take is removed by an earlier pass. The checks of the old backend (ValueLowering.check, the collision checks of Foundation.sources) become the first target-side pass. Alternatives: Scheme scripts (rejected by the product owner), or passes inside the backend (rejected: the middle end is host-run so other backends share it).

NAD-1. Node addresses follow the upstream draft (PRD D11)

The typed address (artifact selector, format, root, typed steps, revision, optional guard) and its URI writer and parser follow finos/morphir docs/spec/ir/node-addresses.md, draft 0.1.0-draft.1. This change adds the type, the canonical writer, the parser for the fixture cases that need no resolver, and the walk that gives each node its address. The resolver, the guards and the sidecars belong to the decorators change. The format is data in the address, so D4 holds. The address does not carry a source position. If upstream changes the draft, only the writer and the role table change. Alternative: an own scheme (FQName plus path); rejected after the product owner pointed to the upstream contract.

BKD-1. Backend with SyntaxFactory and a layout pass (PRD D1, D6, D8, D12)

The backend has three stages: plan (names, files, SDK calls, profile and options), syntax (SyntaxFactory, one CompilationUnitSyntax per file) and layout (NormalizeWhitespace, then a Morphir layout pass, because NormalizeWhitespace alone puts the close brace of a switch expression on the last arm line). It uses no Workspaces assembly. The output is C# 15 only: plain records with the equality of plain C#, closed record or union for custom types, namespace-level types for type-only modules and static classes for modules with values. For targets below net11.0, one polyfill file with internal types behind guards (IsExternalInit below NET5_0, CompilerFeatureRequiredAttribute below NET7_0, UnionAttribute, IUnion, IsClosedTypeAttribute below NET11_0). The consumer needs SDK 11 and LangVersion 15. Tail-recursive LetRecursion is a while loop in every profile. For the worked example, Order becomes:

public closed record Order;
public sealed record Market(decimal Quantity) : Order;
public sealed record Limit(decimal Quantity, decimal Price) : Order;

Alternatives: keep text emission (rejected by the product owner on 2026-11-15), or SyntaxGenerator from Workspaces (does not run under Native AOT).

SUM-1. Custom types: closed form or union form (PRD D7, D14, D15)

The preferred form of a Morphir custom type is a closed record with sealed record cases. A C# union Shape(Circle, Rect) is accepted and lowers to type Shape = Circle Circle | Rect Rect (a constructor with the local name of the case type and that type as its one argument). The frontend refuses a union with a case that is a type parameter or a tuple, two unions in one module that share a case type (constructor names must differ), and code that reaches the state with no case: default, a null arm, .Value and IUnion. The backend writes a union for a custom type in which each constructor has one argument that is a reference with the constructor's name, and the closed form otherwise, so the round trip is exact. A mixed type takes the closed form and fails if a case name equals a module type name. The analyzer reports an older encoding (an abstract record with a private constructor and nested cases), and a code fix in the IDE-only assembly changes it to the closed form; it never rewrites a union.

EQL-1. Plain equality by default (PRD D8, D16)

The rule that NaN is not equal to NaN in a record is a morphir-dotnet choice (ValueSemantics.cs), not an upstream rule. The default is the equality of plain C#; records and unions are written with no added members. The IEEE option adds the four Morphir members to a record, and the same members with == and != to a union (a plain union has no ==: CS0019). Morphir.SDK.CSharp accepts plain records and plain unions in Basics.Equal and in its collections. The frontend refuses a function-typed field and null, which the SDK rejects at run time. Decided in the SDK task: a double in an SDK value (a list, a dictionary, a Maybe, a Result) keeps comparing as a double, so NaN in a list is not equal to NaN; the existing conformance cases need it. A plain record or union compares with its own equality, so a record with a NaN field equals its copy. The two differ only for NaN; the IEEE option on the record makes it follow the list. A plain record or union that holds a function-typed field, directly or through a record, fails with NotSupportedException in equality and in hashing.

LOP-1. Loops lower by shape with one recognizer (PRD D6)

One recognizer in the analyzer assembly classifies a loop for both the diagnostic and the lowering, so the two cannot disagree. SemanticModel.AnalyzeDataFlow gives the state, AnalyzeControlFlow on the body (not on the loop statement) gives the exits, and the IOperation tree shows writes to anything other than a local or a parameter. A for loop's declared variables count as state. The spike classified ten loops the same under JIT and Native AOT. The worked example's Total loop writes one local, so it is List.foldl. The backend writes the loop form under the imperative profile and the functional form under the functional profile. List.filterMap has its own form, a FilterMap call of the SDK, because Where then Select is the form of List.map over List.filter. Round trip: IR to C# to IR is equal, source locations left out, compared with the backend input after the target-side passes.

OPT-1. One option record, two carriers (PRD D16)

Each handling option has an attribute and a morphir.toml key with the same values, and both feed one record. The nearest carrier wins: command line, member attribute, type attribute, assembly attribute, morphir.toml, profile default. A frontend option (loop lowering) changes the IR. A backend option (traversal, tail form, float equality) changes only the C# text, so the frontend writes it as metadata of the declaration and the backend writes the attribute back. The current IR has annotations on specifications only, so the carrier for a definition is an implementation choice recorded in the first task of group 6; the proposed V4 4.1.0 facts are a candidate. An option never makes refused code accepted. An equality option on a type needs partial, because an attribute cannot change how compiled C# compares records; the analyzer reports a type that is not partial.

BLD-1. MSBuild target and source generator on one core (PRD D10, D12)

The generator is a thin C# IIncrementalGenerator: each *.morphir.json additional file goes through the pipeline function and the files go to AddSource. It compiles against the oldest Roslyn that it supports, ships FSharp.Core beside it, and reports a failure as a diagnostic. The MSBuild target writes the same files to the intermediate folder before compilation and sets LangVersion 15. The same model gives the same bytes through the CLI, the target and the generator. Not tested: Visual Studio, Rider and VS Code, and a net8.0 runtime; the support matrix says so.

AOT-1. Built-in in all offerings (PRD D13)

Both hosts register the C# frontend, the backend and the passes. The Native AOT morphir links Microsoft.CodeAnalysis and Microsoft.CodeAnalysis.CSharp 5.12.0 and embeds the reference assemblies (about 6.3 MB more). The publish gate accepts the Roslyn IL2104 summary and keeps per-site errors for NuGet.* and Newtonsoft.Json. A closure check proves that the executable has no Workspaces or code fix assembly. The size limit of .agents/aot-optimization.md (20 MB guideline) moves to a recorded new value. Native AOT output must equal JIT output for the frontend and the backend.

Risks and trade-offs

RiskMitigation
One pull request holds steps 1 to 7. It is large and hard to review.The task groups keep the PRD step order and each group lands as its own commit with its own tests and docs, so a reviewer can read one commit at a time. The product owner chose this on 2026-11-15.
The Native AOT morphir grows by about 28 MB (about 34 MB with embedded references).Measured, recorded and accepted in the PRD (D13). The size check of group 9 records the size and fails on growth above the recorded limit.
The generator does not load in a compiler older than its Roslyn.Compile against the oldest supported Roslyn and test the SDK matrix in the build.
The generator in Visual Studio, Rider and VS Code is not tested. FSharp.Core beside the generator can conflict in the .NET Framework process of Visual Studio.The support matrix lists them as not tested. A later task tests them when a machine is available; no claim before.
The upstream node address draft changes.Only the writer and the role table depend on it. The application list holds the lineage until upstream decides (#1178 to #1180).
Roslyn names a value differently under Native AOT and JIT.No ToString() of a Roslyn enum in IR or codes. An AOT-equals-JIT test covers the frontend and the backend.
Removing the old backend breaks users who read generated abstract class output or C# 14.The proposal marks it BREAKING. Release notes and the docs give the new shape; the old project goes away only after the new backend passes the old conformance cases that still apply.
Plain equality differs from Elm for a record that holds NaN.The IEEE option restores it. The docs name the difference.

Migration plan

  1. Add the new projects and keep Morphir.CodeGeneration.CSharp while groups 1 to 4 land.
  2. Switch the csharp target to the new backend in group 5 and run the old conformance cases against it. Cases that test C# 14 output or the abstract class shape are replaced, not ported.
  3. Remove Morphir.CodeGeneration.CSharp in the same group after the new backend passes. Rollback before merge is reverting the commit of that group.
  4. The release notes state the breaking output change and that C# 14 output is gone.

Open questions

  • Metadata carrier for a backend option on a definition (OPT-1). It does not change the specs or the task breakdown; group 6 task 6.1 decides it and records the choice here.
  • Collections and NaN (EQL-1). Decided in the SDK equality task: collections keep the double comparison, plain records keep their own. See EQL-1.
  • The new size limit of the Native AOT morphir. The task that measures the final build sets it.

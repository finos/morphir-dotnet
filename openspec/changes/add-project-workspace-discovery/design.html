Context

See proposal.md for motivation. WorkspaceDiscovery currently walks for .git and .morphir independently and prefers the Git result. ManagementScenario registers that existing type for artifact-management commands. The preceding shared-configuration campaign supplies typed primary parsing and resolution, but has no filesystem discovery.

Goals and non-goals

One shared policy must produce the same roots, member inventory, and source evidence from native and mounted trees. Keep file access at host boundaries and preserve current artifact-management behavior through its legacy entry point. This campaign adds no editing or CLI command family.

Decisions

DISC-1. Run the root walk over explicit file-tree evidence

Add project/workspace records and discovery policy in Morphir.Configuration. The policy consumes known directory/file evidence and requests missing listings/content through a small shared boundary; Morphir.Configuration.IO fulfills those requests for native paths or in-memory adapters. Parse nearest primaries first, remember nearest project, and stop at the nearest merged workspace declaration or supplied boundary. This avoids having each host implement a different upward walk or using Git as a project-system declaration. Alternative considered: Separate per-host root walkers were rejected because their stopping rules would drift.

LAY-1. Use one candidate inventory per logical location

Enumerate root, hidden, and dot-config stems as alternatives within each format group. Supplemental morphir-workspace.json contributes first in the JSON group. Check every same-group alternative before selecting values, preserving all ambiguous paths in the error. A hidden config's parent project location anchors relative paths; the hidden directory does not become a member. Alternative considered: Choosing a layout by precedence was rejected because it would hide ambiguous candidates.

MEM-1. Separate root discovery, membership, and selection

After selecting a workspace, expand root-relative members/exclusions with deterministic path ordering, preserve virtual versus root-project identity, and record invalid literal members rather than silently dropping them. Selection is a separate pure operation over canonical member paths, unique names, invocation ownership, and default_member. This lets an editor inspect all projects without guessing the command's intended selection. Keep the owning workspace context separate from inherited member settings; it supplies topology and output-root semantics without copying the root's project/workspace subtrees into the member document. Alternative considered: Combining discovery with one command's selection was rejected because editors and aggregate migration need the complete inventory.

HOST-1. Inject machine paths and environment explicitly

The IO adapter resolves native platform directory inputs and builds system/global alternatives, adjacent personal files, and active-profile requests. The policy handles format ambiguity and isolation consistently. Reject relative XDG_CONFIG_HOME and let nonempty MORPHIR_HOME relocate only the home alternative. A browser host supplies its permitted mounts and no ambient native path access. Alternative considered: Reading ambient platform state inside pure rules was rejected because mounted hosts cannot reproduce or authorize it.

COMP-1. Leave legacy discovery wired to existing callers

Introduce new document-aware APIs and opt new configuration/project consumers into them. ManagementScenario's existing Git-first entry point remains unchanged. Regression-test its existing tests alongside new native/in-memory parity fixtures; a broad replacement of WorkspaceDiscovery would silently alter artifact installation locations. Alternative considered: Replacing the legacy discovery implementation in place was rejected because it could change existing artifact locations.

Risks and trade-offs

RiskMitigation
A member's project primary hides a parent workspaceExercise member/src invocations, nested declared workspaces, and nearest-project fallback with observed read lists.
Directory enumeration or symbolic links escape host permissionsNormalize paths, enforce the supplied boundary, skip discovered links, and have each adapter return typed access failures.
Glob expansion creates hidden or duplicate projectsKeep config directories out of members, sort canonical paths, diagnose duplicate names and missing/invalid literal members.

Migration plan

Ship the new library entry points after shared configuration lands. Keep current tooling discovery as a compatibility path; new config inspection will use the new API. Document the different declaration rule and avoid changing existing Git-first callers in this campaign. Rollback is removal of the new consumer registration, with no file changes.

This campaign is complete only after one reviewable PR has landed on main and the campaign-owned worktree and local/remote branches have been removed. Passing tests or opening a PR alone is not completion.

  4. Merge through the repository's normal review and required-check policy. No force push, admin bypass, deployment, or release is implied by this plan.

After confirming the worktree has no unique uncommitted/unmerged work, remove that campaign's worktree and local/remote branches through the owning workspace/forge tools. Check they are absent. Do not force removal or prune unrelated artifacts.
  6. Report the PR URL, landed SHA, check/review evidence, archive/spec-sync outcome, and cleanup results. Preserve unrelated work and unresolved recovery journals; if cleanup or recovery is blocked, report it and keep the campaign unfinished.

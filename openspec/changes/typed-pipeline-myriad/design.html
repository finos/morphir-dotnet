Context

See the proposal for motivation. These facts about the current code constrain the design:

  • Attributes outlive decoding. Decode.Model holds PackageDefinition<JsonElement, JsonElement>, and Emit.fs:537 reads those elements during generation. Transpiler.fs:13 keeps the document alive with use document across decode and emit. A parser that returns the model must not dispose the document its elements point into.
  • Order is not structure. Backend module order is topological with module path as the tie-breaker, and it can alternate between directories. Directory order in a tree cannot express it, and today's manifest.json holds it.
  • Validation is inside emission. Emit.generate runs Validate.scopes and name-collision checks before emitting, and failures travel as the internal GenerationFailure exception.
  • The plugins are not ready. Their Transform functions are stubs over Value<unit, unit>. Optimizer.optimizeValue matches functions by local name only, folds int64 although Int maps to int32, treats literals of different types as comparable, and does not descend into several value forms. TypeValidator.inferValueType reports an error for any variable not in its environment and a warning for every reference.
  • The host has one output path. Myriad runs once per module and returns one source file, so the task runs a planning pass and then the host N times.
  • C# calls these libraries. GenerateMorphirModules.cs is C#. It can use generics, unions and modules, but not inline SRTP functions.
  • Tests are not all reachable through plain dotnet test. TUnit projects fail under VSTest on the .NET 10 SDK, so verification uses each test project's configured runner or the Nuke targets.

Goals and non-goals

Goals: no obj in any public pipeline contract; one file and diagnostic model shared by the pipeline and the F# backend; no loss of the build task's safety behaviour; a real pipeline in production use through Myriad.

Non-goals:

  • Streaming JSON decoding or module-at-a-time processing. A stream source avoids holding raw bytes in the pipeline. Once decoded, the IR is in memory, and JsonDocument builds a full document first.
  • Plugin chains that change the model type mid-run. A compiler is the one step that leaves the model type, and a typed composition step can be added when a second use needs it.
  • Caching the N+1 decodes of the Myriad path, a Morphir CLI command, IR 4+ and document trees.
  • A real F# frontend. The directory path and per-file runner are proven with small fixtures.

Decisions

TYPE-1. Generics in the core, SRTPs and flexible types at the edges

Requested direction: no obj contracts, with generics, SRTPs or flexible types preferred. SRTP and flexible constraints exist only on inline or generic functions, so they cannot be held in a record or list. A processor must store its stages, and C# cannot call SRTP functions. Stored stages are therefore plain generics:

type Parser<'T>   = TreeNode -> Result<'T, ParseError>
type Plugin<'T>   = { Name: string
                      Configure: PropertyBag -> PropertyBag
                      Transform: 'T -> VFile -> 'T option * VFile }
type Compiler<'T> = 'T -> VFile -> VFileTree

Parser.forFile : (VFile -> Result<'T, ParseError>) -> Parser<'T>
Plugin.focus   : ('Outer -> 'Inner) -> ('Inner -> 'Outer -> 'Outer)
                 -> Plugin<'Inner> -> Plugin<'Outer>

SRTPs and flexible types are used where a value is consumed immediately: an inline VFile.create that accepts a string, byte buffer or stream source through a static resolution helper; an inline Parser.ofParseable for any type with a suitable static Parse member; and #seq<_> parameters on functions such as fromFiles and PropertyBag.ofSeq. Each inline function has a non-inline equivalent (VFile.ofText, ofBytes, ofStream) for C#.

Configure narrows from the whole processor to the processor's data bag. A getter and setter cannot lift a MorphirProcessor<'Inner> to the outer type, so the old shape would make Plugin.focus impossible to write correctly. Every use in the repository only sets data, so no behaviour is lost, and the recursive type between plugins and processors goes away. A plugin that wants to add other plugins is left out until a real one exists.

Plugin.focus lets package-level plugins run on a larger model type without casts. Alternatives: an abstract class hierarchy would add ceremony and still need generics; a boxed core with typed wrappers would keep the failure the change exists to remove.

TYPE-2. One run produces one model, and the input is a tree node

Agreed with the requester. Rename TreeContent to TreeNode and use it as the input, with no new union.

MorphirProcessor.run         : TreeNode -> MorphirProcessor<'T> -> VFileTree
MorphirProcessor.runEachFile : VFileTree -> MorphirProcessor<'T> -> VFileTree
MorphirProcessor.processFile : VFile -> MorphirProcessor<'T> -> VFileTree   // run (File f)
MorphirProcessor.processPath : string -> MorphirProcessor<'T> -> VFileTree

Plugins and compilers only see 'T, so they never handle the union. Parser.forFile spares single-file parsers from matching on it. runEachFile keeps the location of each input file: outputs from a file in sub/ are placed under sub/, and diagnostics move to the output tree with the failing path. A separate per-file TreeProcessor as written in #375 would duplicate this, and would not cover many-to-one input.

TYPE-3. VFile stays non-generic

The model travels through the processor, already separate from the file in Transform. The file carries only source content, path, history, messages and data. A generic VFile<'T> would spread a type parameter through VFileTree and force a change of type at each stage. An output tree holds generated content, and it never needs the model.

TYPE-4. Compilers merge, and a failed run has no files

Each compiler returns a tree. The run merges them in order: files from later compilers are appended, and Metadata is combined with later values winning. Duplicate locations are left for publication to reject rather than being silently resolved. The run does not catch unexpected exceptions from stages, because an expected failure has a typed path and a bug should surface as a bug.

When stages stop. Severity keeps the meaning documented in File.fs, where Error lets the pipeline continue collecting diagnostics and Fatal halts it. Plugins keep running after an Error, so one build can report scope and type problems together. A plugin returning None or a Fatal message stops the remaining plugins. Compilers run only when the file has no Error or Fatal message, so a failed run has no output files.

What reaches the output. The input file is not part of the output. Its messages move to the output tree's Messages, with Path set where it is empty, and its Data merges into the tree's Metadata, with compiler values winning, so data a plugin stores is still readable when the run ends. A failed tree has Path set to the input path and no files. runEachFile copies each run's metadata onto that run's output files, keeping a file's own values, so per-file data cannot collide in one root bag.

When every parser fails. Failures are warnings while another parser can still succeed. Once all have failed, InvalidInput and Failed results become Error messages with their own details, so the real cause leads the list. The generic "No parser succeeded" error is added only when every failure was UnsupportedInput, which says nothing about the content.

DIAG-1. Tree-level diagnostics and richer messages

type VMessage =
    { Severity: MessageSeverity; Message: string
      Path: string option        // new: file the message is about
      Location: string option    // new: logical location, such as a JSON path or module
      Position: SourceRange option
      Source: string option      // stage that produced it
      RuleId: string option }

type VFileTree = { ...; Messages: VMessage list }  // new

type ParseFailure =
    { Path: string option; RuleId: string option; Location: string option
      Message: string; Position: SourceRange option }

[<RequireQualifiedAccess>]
type ParseError =
    | UnsupportedInput of reason: string
    | InvalidInput of ParseFailure
    | Failed of path: string option * cause: exn

This replaces Diagnostic: InputPath becomes Path, Category becomes RuleId, and Location stays. VMessage.describe produces the existing path: rule at location: message format, so build output stays recognizable. hasErrors, collectMessages and statistics include tree-level messages. ParseError carries the rule and location because a parser returns only a Result and has no file to add a message to; without them, Myriad's rejection rules such as unsupported-version would be lost. VFile.warn, VFile.message and friends keep their current signatures, with the new fields set to None, and a new VFile.report : VMessage -> VFile -> VFile adds a complete message. A union of location kinds was rejected for now, because the only consumer formats it as text.

BAG-1. Typed property bag

Requested design. The bag is the last parameter of every function.

type Property<'T>     // name + value type, with member With: 'T -> PropertyValue
type PropertyValue    // a property with its value, non-generic so lists can mix types
type PropertyBag      // opaque

module Property =
    val create  : name: string -> Property<'T>
    val valueOf : Property<'T> -> 'T -> PropertyValue

module PropertyBag =
    val empty    : PropertyBag
    val ofSeq    : #seq<PropertyValue> -> PropertyBag
    val add      : PropertyValue -> PropertyBag -> PropertyBag
    val set      : Property<'T> -> 'T -> PropertyBag -> PropertyBag
    val update   : Property<'T> -> ('T option -> 'T) -> PropertyBag -> PropertyBag
    val remove   : Property<'T> -> PropertyBag -> PropertyBag
    val tryGet   : Property<'T> -> PropertyBag -> 'T option
    val getOr    : Property<'T> -> 'T -> PropertyBag -> 'T
    val contains : Property<'T> -> PropertyBag -> bool

Storage is an immutable dictionary keyed by name and System.Type, holding boxed values. That is the only obj in the design and it is private. Casts cannot fail, because the key includes the type. typeof<'T> is safe under trimming and AOT. A generic VFile<'Data> was rejected because plugins from different assemblies could not add data without changing that type. PropertyBag has custom equality comparing keys and values with Object.Equals, keeping VFile and VFileTree usable with =, and no comparison. VFile, VFileTree, TreeConfig and MorphirProcessor have matching set, tryGet and remove functions taking the owner last. __stay_mutable__ becomes a real field on the builder's state.

No custom operator is added. The docs note that |> and <| share precedence and group left to right, so mixing them in one expression needs parentheses.

SRC-1. Content as a union with re-openable streams

[<Sealed>]
type StreamSource(openStream: unit -> Stream, ?length: int64)   // reference equality

type VFileContent =
    | Text of string
    | Bytes of ReadOnlyMemory<byte>
    | Stream of StreamSource

type VFile = { Content: VFileContent option; ... }

module VFileContent =
    val openRead : VFileContent -> Result<Stream, ContentError>
    val readText : VFileContent option -> Result<string, ContentError>

type ContentError = ReadFailed of path: string option * cause: exn

Requested direction, going beyond unified, whose value is string | Uint8Array per .agents/kbs/vfile-pattern.md. It must be a re-openable source, not a live stream: parsers are tried in order, and an immutable file passed through a pipeline can be read more than once. A StreamSource is a class so that VFile keeps equality, which a function field would remove. VFile.fromDisk path makes a source over File.OpenRead. loadFromDisk uses it and reads nothing, so a missing or unreadable file surfaces when read. Its previous eager text load, including UTF-8 decoding of binary files, goes away. toStringMap returns Result<Map<string, string>, ContentError>, because reading can now fail. Text is written as UTF-8 without a byte order mark, and readText uses a StreamReader that honours a mark. VFile.ofText and its siblings replace the generic boxing constructors.

PLG-1. Make the plugins real and safe

Generalize plugins and helpers from unit attributes to 'ta and 'va, operating on PackageDefinition<'ta, 'va>.

  • Optimizer. Match Value.Reference by fully qualified name against the Morphir.SDK modules. Fold only same-type literals. Skip whole-number results outside the int32 range used by the emitted mapping, division by zero and any non-finite float. Fold only operations in the backend's mapping at Emit.fs:451-473, with semantics confirmed by executing both forms; Basics.and and Basics.or are not in it and are not folded. Traverse all value forms, including let, destructure, pattern match, record and update. Folded nodes keep the attributes of the expression they replace. Statistics become Info messages.
  • Optimizer rewrites beyond folding. The existing boolean short-circuit, literal if and identity lambda rewrites stay in the plugin behind Optimizer.Options, off by default, and the Myriad pipeline runs folding only. Those rewrites run before emission, so they could delete code emission would reject, letting true && x start generating while a && b stays rejected. That would change which models are accepted, which this change promises not to do. Turning them on is a later decision for the backend's supported-model contract.
  • TypeValidator. Build the environment from declared inputs and pattern and let bindings. An unresolved name or unsupported form returns unknown, quietly. Compare only SDK primitive types, and treat every other declared type as unknown, so an alias such as type alias Cents = Int with a body of 5 can never raise a false error on a valid model. Fix the literal types to match the backend's mapping: TypeValidator.fs:52-53 uses Basics:String and Basics:Char while Emit.fs:400-401 uses String.String and Char.Char. Scope errors stay with Validate.scopes, the source of the existing unbound-variable rule. Alias resolution can be added later, because it only finds more errors.
  • PrettyPrinter. Format the real package into a typed property, PrettyPrinter.output, stored on the file so that it reaches the output tree's metadata per TYPE-4. It is not added to the Myriad pipeline.

Morphir.IR.Pipeline.Plugins already references Morphir.Models, so it can name these types. Leaving the optimizer out of Myriad would be safer but would leave the plugin path unproven, and the requested first pipeline includes it. Its risks are limited by the equivalence test in MYR-1.

MYR-1. The backend becomes a pipeline

let internal processor : MorphirProcessor<Decode.Model> =
    pipeline {
        parse (Parser.forFile modelParser)
        uses scopeValidator
        uses (Plugin.focus definition withDefinition (TypeValidator.create ()))
        uses (Plugin.focus definition withDefinition (Optimizer.create Optimizer.foldingOnly))
        stringify fsharpCompiler
    }

Transpiler.generate : VFile -> VFileTree
Transpiler.manifest : Property<ManifestEntry list>   // ModulePath, Location, in dependency order

Keeping JSON alive. modelParser parses from the content's stream with JsonDocument.Parse, then decodes from RootElement.Clone() so that the model's elements do not depend on the disposed document. This costs a brief second copy of the JSON, which matches the memory non-goal. A disposable model or a parser that leaks the document would both add lifetime rules to every stage.

Splitting emission. Validate.scopes moves out of Emit.generate into scopeValidator. Name-collision checks stay with emission because they depend on emitted names. Internal GenerationFailure stays as the backend's internal signal. Each adapter catches it, along with the JSON and decode exceptions currently mapped in Transpiler.fs, keeping the same rule ids: the parser returns ParseError.InvalidInput, while the scope validator and compiler add a VMessage with VFile.report. The scope validator returns None on failure, because later plugins would be typing a broken model.

Removing the old types. GeneratedModule and Diagnostic go away, and Transpiler.Generate(inputPath, json) is replaced. Output files have text content, and ManifestEntry carries the module identity and order. Backend tests read through a small helper in Fixtures.fs, which keeps the mechanical churn in one place.

Proving behaviour. The optimizer's equivalence check compiles and executes car rental and a dedicated fixture with optimization on and off and compares results. This needs an internal option on the backend, Transpiler.generateWith, which is not exposed through Myriad. Reviewed Verify snapshots change only where folding applies, and those diffs are read as part of this work.

MYR-2. The build task becomes a thin caller

  1. Resolve paths and reject output-root collisions between models, as today.
  2. Run Transpiler.generate on a VFile.fromDisk of the model for the plan. On errors, log each with VMessage.describe and fail.
  3. Call validatePublish on the plan, so collisions and bad paths fail before the host starts.
  4. Prepare the host and run it once per manifest entry, writing to a private host output directory, as today. The host's plugin runs the same pipeline and returns the selected module's text.
  5. Build a new tree whose files are StreamSources over the host output, with the manifest's order, and call publish with Manifest "manifest.json".
  6. Return compile items in manifest order. Design-time builds read through readManifest.

Publishing the host's output instead of the plan's keeps the existing contract that Myriad produces the compiled source. This also makes the task the first production user of stream sources. The host output directory stays separate from publication's staging directory, which means one extra copy per file. Merging them would let the task see publication internals, and these files are small. Requirements that the task log diagnostics to MSBuild, time out the host and align FSharp.Core stay in the task.

Morphir.CodeGeneration.FSharp references the pipeline and plugin projects, so they flow into tools/plugin and tasks/net10.0 through the existing wildcard globs in Morphir.Myriad.fsproj. The cold-cache package-tests.fsx is the check that they do.

Risks and trade-offs

RiskMitigation
The optimizer changes the behaviour of generated business logic.Fold only fully qualified SDK functions with confirmed semantics, leave out-of-range results alone, compare on and off behaviour by execution, and review snapshot diffs.
The type validator blocks a valid consumer build.It reports only definite mismatches, and every supported fixture must pass with no warnings. Its coverage is intentionally partial; the F# compiler remains the full check.
Cloning JSON raises peak memory for very large models.Accepted and documented as a non-goal. Stream sources still avoid a separate in-memory string of the model. Measure with car rental and a generated large fixture, and record the numbers.
Adding plugin stages raises the N+1 per-module build cost.Each host invocation repeats the pipeline. Measure the build before and after, and keep the existing accepted-cost note. Caching stays deferred.
Assemblies fail to load from the package because of task or host version conflicts.Run package-tests.fsx early in the Myriad group, before the plugin rewrite is complete, and pin the failure before expanding.
The public API churn invalidates a large number of tests.Each group migrates its tests with it. Assertions that only proved obj plumbing, such as boxed test content, become typed instead of being preserved word for word.
A stream source's file changes between planning and reading.Reads surface as typed errors, and publication compares actual bytes. Consistency across files is not promised.
Name-based property identity collides across libraries.Same name and type means the same value by design. Document a dotted, library-prefixed naming convention.
A temp-directory lock only serializes publishers running as the same user on the same machine.Accepted. Output roots are normally per-project and per-user, staging still prevents partial files, and the alternatives leave a stray file in every output directory or need a writable parent.
Case-insensitive collision checks reject trees that are valid on Linux.Generated output has to work across platforms, and the task already enforces this. A strict option can be added if a real case appears.

Migration plan

  1. Land each task group in order on the feature branch. The repository builds and its tests pass at the end of each group.
  2. Update the pipeline README, plugin guide, backend PRD and unified-file-architecture.md as their groups land. The PRD's current-delivery section says the backend now runs on the pipeline. Leave the completed add-myriad-morphir-fsharp design as its historical record, and note here that this change supersedes its decision against routing through the pipeline.
  3. Consumer rollback: the package's build contract is unchanged, so reverting the commits restores previous behaviour with no consumer change. Generated output is rebuilt from the model on the next build.
  4. Reconcile #375 when this lands. No published packages contain these APIs, so no deprecation period is needed.

Open questions

  • What is the largest model worth measuring? The requester did not name a worst case. The plan is to record peak memory and build time for car rental and a generated large fixture, then decide whether the deferred streaming decode is needed. The answer does not change this design.

Context

See proposal.md for motivation and tracking. The reviewed baseline is merged PR #456, commit 0a7f6ca. This planning checkout is older; implementation first integrates that baseline.

  • IrToolingScenario currently registers only JSON schema verification. The CLI already has a shared host, scenario registration and Foundatio mediator.
  • Transpiler.generate : VFile -> VFileTree parses classic JSON itself. Its internal model, validators and emitter use classic types. V4 generation therefore requires implementation, not just a new parser or a capability flag.
  • Morphir.Models has classic and v4 types/readers. Morphir.Ion reads Ion IR files and trees; its current IrDocument wraps those two families. Do not move that public type in a breaking change.
  • The configuration record currently models cache paths. Its resolver directly reads layered TOML files. It is not yet an ecosystem-compatible generation/project configuration resolver.
  • VFileTree.publish already checks paths, stages files, preserves identical output, tracks ownership and reports changes. Commit-time I/O failure can leave mixed old/new files; this proposal does not claim directory-wide atomic replacement.

Behavior contracts: CLI generation, model loading, and F# generation changes.

Goals and non-goals

Make a resolved generation request reusable by CLI, library and later MEP callers. F# generation from both classic and v4 Libraries is required in this delivery. Every physical representation feeds the same version-appropriate semantic generation path.

Keep configuration codecs, model codecs, generators and filesystem publication independently replaceable. Do not introduce dynamic plugin loading, a new execution engine, a second IR definition, a MEP runtime, project-file generation or configuration discovery in this change.

Source generation targets reusable Libraries. Specs-only generation and Application packaging are not first-delivery capabilities. Unsupported individual v4 constructs have the explicit behavior in GEN-2 below; v4 as a version is supported, not deferred.

Decisions and contract sketches

Snippets describe intended additive APIs. Supporting result/value types are abbreviated; implementation must compile representative consumer snippets as tests. They are not existing APIs or literal MEP wire types.

APP-1. One application handler owns orchestration

Register a generation scenario in the existing CLI builder and a mediator handler in Tooling. The command action only captures overrides, invokes the handler and renders its typed result. Reuse the app host instead of creating a second host for this command. Alternative: calling F# directly from the command action couples flags, codecs and publication to one language.

// Proposed application contracts. Outcome<T> is a typed success/error result.
public interface IGenerationSettingsResolver
{
    ValueTask<Outcome<GenerationSettings>> ResolveAsync(
        GenerateOverrides overrides, InvocationContext context, CancellationToken ct);
}
public interface IModelLoader
{
    ValueTask<Outcome<LoadedModel>> LoadAsync(
        ModelInput input, ModelReadLimits limits, CancellationToken ct);
}
public interface IGenerationBackend
{
    BackendDescriptor Descriptor { get; }
    Outcome<ValidatedBackendOptions> ValidateOptions(BackendOptions options);
    ValueTask<Outcome<GenerationArtifacts>> GenerateAsync(
        BackendGenerationRequest request, CancellationToken ct);
}
public interface IGenerationBackendResolver
{
    Outcome<IGenerationBackend> Resolve(TargetId target, ModelDescriptor model);
}

GenerationSettings contains a resolved input, exact target, structured options and publication policy. BackendGenerationRequest contains the loaded model, target and validated options, but no output directory. GenerationArtifacts holds the output tree and diagnostics. The publisher is a thin host adapter over the existing API, not a new publication algorithm.

CLI overrides --> settings resolver --> resolved request
resolved input --> bounded capture + codec --> retained typed model
target + model --> backend resolver --> F# classic or v4 generation
generated tree --> existing publisher --> publication report

Handle each typed failure before the next stage. Cancellation flows through the handler and adapters; it is checked before starting publication. No automatic codec fallback after recognized malformed input and no automatic backend fallback after provider selection.

MDL-1. Keep semantic IR and retained input together

Add a transport-neutral versioned semantic wrapper in Morphir.Models that references existing classic/v4 distributions. Keep capture and representation descriptors in Tooling. A loader maps the existing Ion result into this wrapper, preserving the original API. Alternative: making all consumers reference Morphir.Ion.IrDocument would bind semantic generation to a serialization package.

// Proposed Morphir.Models shape, using existing distribution definitions.
type DistributionModel =
    | Classic of Morphir.IR.Classic.Distribution.Distribution<JsonElement, JsonElement>
    | V4 of Morphir.IR.V4.Distribution

type VersionedModel = {
    SourceVersion: SourceFormatVersion
    Distribution: DistributionModel
}

// Tooling owns immutable, bounded file/tree snapshots.
// LoadedModel = VersionedModel + ModelDescriptor + RetainedInput.
// RetainedInput retains bytes; it does not claim those bytes equal a JSON view.

Capture once into privately owned bounded storage, then decode that capture. Tree capture bounds entries, aggregate bytes, path length and depth while enumerating, before constructing the virtual tree. Reject links/special files and preserve tree-relative paths. Do not call an unbounded recursive loader and check budgets only after it finishes. Reuse Ion reader limits and add explicit JSON/capture limits, applied before allocation.

JSON uses ClassicJson.readDistribution or the v4 reader. Ion uses IonIr.read or IonIrTree.readDetailed. Exact declared versions remain in SourceFormatVersion even when classic decoder context uses integer 3. A MEP wrapper receives an explicit unsupported-profile diagnostic in this delivery, not a bare-IR parse attempt.

GEN-1. Register providers and declare compatibility

Register one first-party provider, identity morphir-dotnet-fsharp, target fsharp. Its descriptor advertises classic JSON v1/v2/v3 and supported classic 3.0.0/3.1.0 and v4 4.0.0 Libraries. Codec support is declared separately by loaders. Ambiguous providers fail; registration order never selects a winner.

// Composition root, not target-selection logic in the command.
services.AddSingleton<IGenerationBackend, FSharpGenerationBackend>();
services.AddSingleton<IGenerationBackendResolver, RegisteredBackendResolver>();
services.AddSingleton<IModelLoader, RegisteredModelLoader>();
services.AddSingleton<IGenerationSettingsResolver, CliGenerationSettingsResolver>();

Alternative: a switch (target) in the CLI would require modifying the command for every future provider. Static DI registration avoids reflection scanning and keeps trimming/AOT behavior reviewable. A MEP adapter can later implement the same backend contract.

GEN-2. Generate v4 directly through typed version-specific paths

Add a versioned typed entry point. Preserve Transpiler.generate as the strict classic JSON wrapper so Myriad and existing consumers retain their behavior. Dispatch on the semantic model family inside the F# backend, where version semantics belong. Extend the classic path additively and implement v4 validation/emission over v4 types. Share naming, SDK mappings where semantics agree, dependency-order helpers, AST construction and manifest assembly. Do not route v4 through classic JSON or a lossy downgrade.

CFG-1. Resolve settings before invoking generation

In this delivery, CliGenerationSettingsResolver resolves explicit CLI input/target/output and structured backend options. It works outside a project and applies application defaults such as format auto. Backend option validation applies backend defaults such as F# optimize=true. Neither policy lives in the command action.

Model optional overrides separately from resolved settings; avoid using an empty string or Boolean false to mean "not supplied." Relative CLI paths resolve against captured invocation cwd. Future config paths resolve relative to the declaring document, independent of cwd. That distinction belongs in resolver inputs and provenance.

Parse each --option value as JSON first and otherwise keep it as a string; later occurrences replace earlier keys. Clone structured values so they outlive parsing documents. F# accepts Boolean optimize only. Alternatives: backend-specific CLI flags and TOML objects inside the generator would couple transport syntax to public generation APIs.

PUB-1. Reuse owned tree publication

Publish through VFileTree.publish with ManifestMode.Manifest ".morphir-generated.json" and preserve declared compile order. Return its written/unchanged/removed lists. The manifest name is a centralized publication-policy default that future configuration can override, not a literal in the F# emitter.

// Existing publisher API, proposed command policy.
let policy = {
    OutputRoot = resolvedOutput
    Manifest = ManifestMode.Manifest ".morphir-generated.json"
}
match VFileTree.publish policy generatedTree with
| Ok receipt -> reportPublished receipt
| Error error -> reportPublicationFailure error

Reject input/output overlap before publication, especially output equal to or inside an input tree. Backend errors or invalid paths prevent writing. Staging failure preserves old output. Commit-time failure reports possible partial replacement using the existing contract. Do not promise rollback the publisher cannot provide; do not add a second directory replacement engine.

OUT-1. Typed outcomes and source-generated reports

Keep expected failures as typed results and map at the CLI edge. Exit 0 means publication succeeded; 1 means invalid/incompatible model or semantic generation failure; 2 means invocation, option/provider resolution or operational failure; 130 means cancellation. Source-generate serialization metadata for the concrete JSON report DTOs and keep logs on stderr. Parser syntax errors retain System.CommandLine behavior and exit 2; the structured result contract starts after successful argument parsing.

Map reader and generator diagnostics once. Preserve stable existing codes when possible; use generation.unknown_target, generation.ambiguous_backend, generation.unsupported_distribution, generation.invalid_option and publication.failed for application failures. A valid v4 Library is not an unsupported-version failure. New v4 semantic failures use specific unsupported/incomplete/literal-range categories.

The first command selects one target; multi-target execution requires its own output-collision and partial-failure policy.

Future MEP integration

Adapter mapping, not a wire implementation. A future host selects a negotiated target/model tuple before calling a MEP-backed provider. A future F# MEP guest admits its input and invokes the same typed generation service. Neither route needs command-line parsing or output-directory access inside the generator.

Unified testing approach

TEST-1. Organize tests by behavior, parameterize representation

Extend the existing generator tests and compiler/execution helpers into one shared conformance approach. A behavior such as pricing, recursion, visibility or record update has one case identity and one independently specified behavioral oracle. Supported IR versions, codec/layout, API entry point, optimization and publication mode are dimensions of that case. They do not get separate runners, BDD step implementations, evaluators, assertion libraries or testing policies.

Representation adapters can construct or load version-specific fixtures because the schemas differ. They prepare input only. Shared code generates, checks diagnostics, orders/compiles F# files, invokes the generated API and asserts expected behavior. Adapters must not obtain v4 expectations by downgrading to v3 or use one implementation's output as the sole oracle. Cross-version parity supplements independently chosen expected values.

// Illustrative common test shape, not separate v3/v4 suites.
type GenerationCase = {
    Id: string
    Representations: RepresentationExpectation list
    ExpectedBehavior: BehaviorExpectation
}

let cases = [ pricing; recursion; recordUpdates; incompleteBodies ]

for case in cases do
    for representation in case.Representations do
        // The same runner handles success, refusal and explicit non-applicability.
        runGenerationCase sharedHarness case representation

The expectation matrix records supported combinations, expected refusal codes, and genuinely unrepresentable combinations with reasons. Historical v1/v2 JSON coverage does not imply an invented Ion v1/v2 encoding. Required combinations missing from the matrix fail a coverage assertion. Declared incompatibility is visible in the case inventory and report, not an unexplained runtime skip or blanket expected failure.

V4-only semantics, such as inferred-type contradictions or incomplete bodies, add cases to this corpus with explicit applicability. They still use the same runner, diagnostic assertions and reporting. Focused codec/version adapter unit tests remain appropriate; they do not form an alternate end-to-end strategy. Preserve existing regression snapshots and share behavioral assertions. Separate source snapshots require a genuine expected representation difference, not copied per-version baselines.

Alternative rejected: independent classic/v4 test suites with their own fixture catalogues, compiler runners and expected results. That duplicates infrastructure and permits behavior and quality gates to drift. Group 4 in tasks.md is an implementation sequence for v4 semantics, not authorization to build a second testing system.

Risks and trade-offs

RiskMitigation
V4 support becomes a parser-only claimRequire nonempty v4 compilation/execution and JSON/Ion/tree parity before completion.
Classic and v4 emission driftKeep typed version-specific semantics, share target helpers, and run cross-version behavior fixtures. Do not force v4 through a narrower classic model.
Testing fragments into version-specific strategiesEnforce TEST-1: one behavior corpus, runner, oracle approach and quality gates; explicit version/format applicability and refusal expectations.
V4 literals exceed current F# ABIDocument the scalar profile and prove exactness or reject. Never round decimals or split Unicode scalars.
Raw retention doubles memory or captures changing inputCapture once within finite budgets; use privately owned snapshots and decode from those bytes.
Public contracts mimic an unstable MEP draftUse small semantic/application contracts and protocol adapters; preserve representation data without copying wire DTOs.
Config examples are mistaken for delivered functionalityMark every file-backed example future-only; first-delivery parser refuses unimplemented flags.
Publisher commit failure is mistaken for atomic rollbackReport publication failure honestly and preserve its existing documented staging/commit distinction.
Native AOT exposes new trimming issuesStatic provider registration, source-generated report serialization and published-executable acceptance tests.

Migration plan

  1. Integrate merged PR #456 into the implementation branch without destructive reset, and establish the feature PRD and status table.
  2. Add the model/settings/backend contracts and typed classic entry point while keeping existing callers and snapshots passing.
  3. Implement v4 validation and generation with nonempty executable fixtures before advertising v4 capability.
  4. Add bounded codec adapters, CLI orchestration and owned publication with matching tests/docs at each stage.
  5. Run the implementation checklist, including full relevant tests, formatting, coverage and trimmed/AOT generation. Review before landing.

No IR wire format, installed-tool state or production data migration is required. Roll back by reverting the additive command/adapters and new generation path while retaining the legacy API. Generated output changes are governed by its ownership manifest; do not delete unowned files during rollback. Future MEP/configuration implementations are separate changes.

Context

See proposal.md for the reason. The requirements are in specs/extension-registry/spec.md. The current state:

  • One composition, two hosts. src/Morphir/Program.cs builds the CLI with MorphirCli.CreateBuilder(...).AddScenario<...>(). dotnet-morphir (src/Morphir.Tool/Program.cs) calls Morphir.Program.Main(args), so the two hosts cannot tell themselves apart today. VersionInfo is internal to each entry assembly, so Morphir.Tooling cannot read the host version.
  • Backends are already static. GenerationScenario registers FSharpGenerationBackend and CSharpGenerationBackend as IGenerationBackend through TryAddEnumerable. Each has a BackendDescriptor with Identity (morphir.csharp, morphir.fsharp), Target and per-family BackendCapability version sets. RegisteredBackendResolver selects from the same set.
  • The extension command is static. ManagementScenario.CreateExtensionCommand() builds it with no service provider. Since #489, every dist, tool and extension subcommand fails through NotImplemented(group, subcommand) with exit code 1 and a link to its tracking issue (#492 for extension), and CliManagementCommands.feature checks this. The records in Features/Management/ExtensionCommands.cs and ExtensionHandlers.HandleList have no callers.
  • Hosted commands exist. MorphirCliBuilder.AddCommand(Func<IServiceProvider, Command>) builds a command after the container is built. GenerateCommand uses it.
  • MEP shape. The MEP contract (spec/mep/contract/src/mep.gleam in finos/morphir, 0.2.0-draft.1) defines ExtensionInfo { id, name, version, description?, types, author?, homepage?, license?, min_sdk_version? }, ExtensionType with the wire values frontend, backend, transform, validator, workspace, and BackendCapability { targets, ir_versions, generate }.
  • Constraints. The morphir executable is Native AOT and trimmed. No reflection-based discovery, no assembly loading. JSON uses source-generated contexts. Stdout carries command output only.

Goals and non-goals

Goals: registry and generation contracts in which invalid values cannot be constructed (TYP-1), written in F# with a C# edge (LANG-1, FFI-1); one registry type that the later PRD steps extend (configured extensions in step 2, installed extensions in step 3) without a change to its shape; one source of truth for generator identity, shared with generate; a host identity that both hosts set explicitly.

Non-goals: the selection rule; a change to RegisteredBackendResolver behavior (its inputs become typed, GEN-1); MEP wire types or JSON-RPC; any external runtime; registration of the pipeline plugins (PLG-1).

Decisions

LANG-1. The domain is F#; the CLI edge stays C#

AGENTS.md says "F# for ADT-heavy components where appropriate". The registry is almost entirely parsed values and closed unions, so its domain goes into a new F# project. The C# code keeps the parts that only C# can do or that are thin glue.

ProjectLanguageHolds
src/Morphir.Extensions (new)F#The parsed values (TYP-1), the registry unions and records (REG-1), ExtensionCatalog and RegistryError (REG-2), IExtensionSource, TargetId (GEN-1), and the wire values and diagnostics that the output edge needs. It references Morphir.Models (for Versioning and SourceFormatVersion) and nothing from the CLI.
src/Morphir.ToolingC#BackendExtensionSource (it reads the C# IGenerationBackend), DI registration, ExtensionListCommand, the JSON report record and its JsonSerializerContext.
tests/Morphir.Extensions.Tests (new)F#Expecto and Expecto.FsCheck, as the other F# test projects use.

What must stay in C#: the System.Text.Json source generator runs only in C# and does not support F# unions; System.CommandLine and the scenario builder are C#; any Foundatio.Mediator handler is found by a C# source generator.

The new project sets <Nullable>enable</Nullable>, <TreatWarningsAsErrors>true</TreatWarningsAsErrors>, <IsTrimmable>true</IsTrimmable>, <EnableTrimAnalyzer>true</EnableTrimAnalyzer>, <IsAotCompatible>true</IsAotCompatible> and <GenerateDocumentationFile>true</GenerateDocumentationFile>. With F# nullness on, the assembly carries nullable metadata, so the C# compiler in Morphir.Tooling (nullable on, warnings as errors) refuses a null passed to a non-nullable F# parameter. Without it, C# treats F# types as "oblivious" and gives no warning. The project packs with the same settings as Morphir.Tooling, so a package that contains Morphir.Tooling can resolve it.

This also fits PR #495: Morphir.Mep is F#, so the later mapping between the registry types and the MEP types is F# to F#.

Alternatives: all C# with abstract-record unions (the previous draft; no exhaustive matching, and every union needs _ => throw arms); C# 15 union types (not released; on net10.0 they need preview and polyfills, see Open questions); put the types in Morphir.Models (that project is the published IR model package, not tooling).

FFI-1. F# types are shaped for their C# callers

The project skill fsharp-csharp-interop (.agents/skills/fsharp-csharp-interop/SKILL.md) holds the full rules and examples. Apply them only to the surface that C# calls: the parsed values that C# parses or constructs, IExtensionSource, ExtensionCatalog, the wire values and diagnostics, and TargetId. The rules that this change uses:

NeedShape
C# names and callsStatic members on the type (ExtensionId.Parse(text)), or [<CompiledName>] on module functions. Tupled parameters, never curried ones.
Parsing from C#TryParse(text: string | null, [<Out; MaybeNullWhen(false)>] result: byref<T>, [<Out; MaybeNullWhen(true)>] failure: byref<ParseFailure>) : bool, beside the F# Parse : string -> Result<T, ParseFailure>. Not byref<T | null>: F# does not write byref element nullness into the metadata, so C# would read both values as never null (found while applying task 2.3).
Branching on a union in C#Avoid it: put the decision in an F# function. Where C# must branch, add a Match member with one Func for each case, so the signature makes C# handle every case.
Optional valuesT | null on the C# surface, option inside F#.
CollectionsIReadOnlyList<T>, ImmutableArray<T> or NonEmptySet<T> on the surface. Never F# list, Set or Map.
Equality, order and text[<CustomEquality; CustomComparison>] with ordinal comparison where order matters (ExtensionId). An explicit ToString() override on every type: the default prints through reflection (%A), which is not AOT-safe.
No invalid defaultParsed values are reference types. Never [<Struct>]: default would skip the parser.

A reviewer agent (fsharp-csharp-interop-reviewer) checks a diff against these rules. The skill and the agent are already in the repository, for every supported coding agent (see .agents/skills-reference.md). Each task group runs the reviewer before it is complete.

TYP-1. Parse, don't validate: every domain value is a parsed type

No registry or generation contract holds a raw string, a C# enum or a flag that must be checked later. A parsed value is a single-case union with a private case, so only its own module can build it:

[<CustomEquality; CustomComparison>]
type ExtensionId =
    private | ExtensionId of string
    member this.Value = let (ExtensionId v) = this in v
    override this.ToString() = this.Value
    override this.Equals other = match other with :? ExtensionId as id -> String.Equals(this.Value, id.Value, StringComparison.Ordinal) | _ -> false
    override this.GetHashCode() = StringComparer.Ordinal.GetHashCode this.Value
    interface IComparable with member this.CompareTo other = String.CompareOrdinal(this.Value, (other :?> ExtensionId).Value)
    static member Parse(text: string | null) : Result<ExtensionId, ParseFailure> = ExtensionId.parse text   // F# callers
    static member TryParse(text, [<Out; MaybeNullWhen(false)>] result: byref<ExtensionId>,
                           [<Out; MaybeNullWhen(true)>] failure: byref<ParseFailure>) : bool = …                  // C# callers
    static member Create(literal: string) : ExtensionId = …   // literals in source code; throws; a unit test calls each literal

[<RequireQualifiedAccess>]
type ParseFailure =            // turned into a diagnostic code and message only at the output edge
    | Empty of field: string
    | TooLong of field: string * limit: int
    | InvalidCharacter of field: string * index: int
    | InvalidSegment of field: string * segment: int
    | InvalidVersion of field: string * error: Versioning.ParseError

The parsed types and their rules:

REG-1. Registry types in the shape of MEP, mapped to Morphir.Mep later

[<RequireQualifiedAccess>] type MorphirHost = Native | DotnetTool            // "morphir", "dotnet-morphir"
type HostIdentity = { Host: MorphirHost; Version: ReleaseVersion }
[<RequireQualifiedAccess>] type HostAvailability = AllHosts | Only of MorphirHost   // an empty host set cannot exist
[<RequireQualifiedAccess>] type ExtensionDelivery = BuiltIn                   // Process of … and Wasm of … in later steps
[<RequireQualifiedAccess>] type ExtensionType = Frontend | Backend | Transform | Validator | Workspace

type BackendClaim = { Targets: NonEmptySet<TargetId>; IrVersions: NonEmptySet<SourceFormatVersion> }

[<RequireQualifiedAccess>]
type ExtensionCapability =
    | Backend of BackendClaim                                                  // more cases in later steps
    member this.Type = match this with Backend _ -> ExtensionType.Backend      // exhaustive; no wildcard

type ExtensionIdentity = { Id: ExtensionId; Name: ExtensionName; Version: ReleaseVersion; Description: ExtensionDescription option }

type ExtensionEntry =
    { Identity: ExtensionIdentity; Delivery: ExtensionDelivery; Hosts: HostAvailability
      Capabilities: NonEmptySet<ExtensionCapability> }
    member this.Types = this.Capabilities |> NonEmptySet.map (fun c -> c.Type)     // derived, never stored
    member this.IsAvailableIn host = match this.Hosts with HostAvailability.AllHosts -> true | HostAvailability.Only h -> h = host

What the types rule out:

  • An entry with no types. A capability is required, so there is always at least one type.
  • Types that disagree with the claims. Types come from the claims.
  • An entry for no host.
  • A backend claim with no target or no IR version.
  • A generate flag set to false on a backend claim. Generation is the only backend operation in MEP, so the output edge writes generate: true for every backend claim.

The F# compiler checks every match on these unions, with no wildcard arm. Each union has a WireValue member (for example "backend", "built-in", "dotnet-morphir"), so the C# output edge reads text and never branches on a union (FFI-1). The C# entry points build hosts with the generated static members MorphirHost.Native and MorphirHost.DotnetTool.

The identity holds only the MEP members that a built-in fills now. author, homepage, license and min_sdk_version come with parsed types when a step needs them. Delivery, hosts and availability are morphir-dotnet additions. They never go on the MEP wire.

When Morphir.Mep lands (PR #495), add one F# mapping from these types to the MEP ExtensionInfo and ExtensionCapabilities, and one parser from MEP messages into them. Do not replace the registry types: they carry the additions and the invariants.

Alternatives: string records validated by the registry (the first draft; the checks move away from the data, and an invalid entry can exist); wait for Morphir.Mep (this blocks step 0 on PR #495, which the PRD rules out); reuse Features/Management.ExtensionInfo (it models installed versions, not identity).

REG-2. Static registration through IExtensionSource; the catalog cannot hold a duplicate

type IExtensionSource =
    abstract Entries: IReadOnlyList<ExtensionEntry>

[<RequireQualifiedAccess>]
type RegistryError =
    | DuplicateIds of NonEmptySet<ExtensionId>
    member this.Diagnostics : IReadOnlyList<Diagnostic> = …   // code "extension.duplicate_id", message names every id

[<Sealed>]
type ExtensionCatalog =                                   // private constructor; ids unique; ordinal order by id
    member Host: HostIdentity
    member Entries: IReadOnlyList<ExtensionEntry>
    static member create: HostIdentity * seq<ExtensionEntry> -> Result<ExtensionCatalog, RegistryError>        // F#
    static member TryCreate: HostIdentity * IEnumerable<ExtensionEntry> * [<Out; MaybeNullWhen(false)>] catalog: byref<ExtensionCatalog>
                             * [<Out; MaybeNullWhen(true)>] error: byref<RegistryError> -> bool                    // C#

The C# ExtensionRegistry reads every IExtensionSource and the HostIdentity from the container, and calls ExtensionCatalog.TryCreate. A catalog value always has unique ids, so no later code checks for them. On failure the command writes error.Diagnostics and exits with code 2.

Alternatives: assembly scanning or MEF (not AOT-safe, and the PRD forbids it); attributes plus a source generator (more than two built-ins need; it can come later without a change to IExtensionSource); a static list in Program.cs (it drifts from the backend registrations).

REG-3. Backend entries come from the registered backends

The C# BackendExtensionSource takes IEnumerable<IGenerationBackend> and makes one entry for each backend. It does no parsing: BackendDescriptor already holds parsed values (GEN-1).

  • Identity: Descriptor.Id, Descriptor.Name, Descriptor.Description, and the host's ReleaseVersion.
  • Delivery BuiltIn, hosts AllHosts.
  • One capability, a backend claim with Descriptor.Target and the union of the capability versions. An F# helper, ExtensionEntry.BuiltInBackend(...), builds it, so the C# code does not construct union cases by hand.

The two backends declare ExtensionId.Create("morphir.csharp") and ExtensionId.Create("morphir.fsharp"), with the names "C# generator" and "F# generator". The list and generate share one source of truth, and a test checks that they agree.

GEN-1. The generation contracts hold parsed values

The registry reads the generation contracts, so those contracts hold parsed values in this change. The types come from Morphir.Extensions. The contracts themselves stay in C#.

ContractTodayAfter
TargetIdC# readonly record struct TargetId(string Value)The F# parsed value (TYP-1), with the ExtensionId grammar. The C# struct is removed.
BackendCapability.VersionsImmutableHashSet<string>NonEmptySet<SourceFormatVersion>; Supports compares model.Version by value, so the exact declared spelling still decides the match
BackendDescriptor.IdentitystringExtensionId Id, plus ExtensionName Name and ExtensionDescription? Description
BackendDescriptor.CapabilitiesImmutableArray<BackendCapability>NonEmptySet<BackendCapability>

generate behavior does not change. CliGenerationSettingsResolver parses --target with TargetId.TryParse. A parse failure gives the same unknown-target invocation failure, with the same message and list of available targets, as a well-formed unknown target does today. The backend report field is ExtensionId.ToString(), so it is still morphir.csharp or morphir.fsharp. The existing generate tests and the PowerShell contract scripts run unchanged and pass.

ModelDescriptor, SourceFormatVersion and the option parsing are already typed, and they do not change.

ID-1. Extension ids may contain dots, as a documented superset of upstream

The upstream rule (crates/morphir-distribution/src/domain/identity.rs in finos/morphir-rust) allows one lowercase portable token: [a-z]([a-z0-9-]*[a-z0-9])?, at most 238 characters. It refuses morphir.csharp. morphir-dotnet accepts one or more such tokens joined by dots (decided 2026-11-07). This keeps the published backend identities, and a namespace prefix such as morphir. stays possible.

Each segment follows the upstream token rule, so an id still has no empty segment, no . or .. segment, and no leading or trailing dot. Ids stay portable as file names: morphir.csharp.json is valid on every supported platform. Until upstream accepts dots, a dotted id is a morphir-dotnet extension. Built-ins never go into the upstream store, so step 0 is not affected. PRD step 3 must refuse to write a dotted id into the shared upstream store or locks until upstream accepts it. The closeout of this change sends the proposal upstream (task 9.2).

Alternatives: rename to morphir-csharp everywhere (this breaks the published backend report field); keep two identities, one for the extension and one for the backend (one backend would have two names).

HOST-1. Each entry point states its host

// src/Morphir/Program.cs
public static int Main(string[] args) => Run(args, new HostIdentity(MorphirHost.Native, ReleaseVersion.Create(VersionInfo.Version)));
public static int Run(string[] args, HostIdentity host) { /* existing body; registers host as a singleton */ }

// src/Morphir.Tool/Program.cs
private static int Main(string[] args) =>
    Morphir.Program.Run(args, new HostIdentity(MorphirHost.DotnetTool, ReleaseVersion.Create(VersionInfo.Version)));

VersionInfo.Version comes from the build (0.0.0-dev when no version is set). ReleaseVersion.Create throws at start if the build writes a value that is not SemVer. A build test runs --version and parses the output, which catches this before release. If PR #495 has landed when this change is applied, add HostIdentity to its CreateApp(string[] args, Action<MorphirCliBuilder> extend) seam instead of adding Run. --version stays as it is.

Alternatives: read RuntimeFeature.IsDynamicCodeSupported (true for a JIT test run of the morphir project, so it reports the wrong host); read the process name (it is dotnet when the tool runs as dotnet dotnet-morphir.dll).

HOST-2. Entries declare their hosts; availability is computed

A host lists every entry it knows, including entries for the other host only, and marks those as not available. The PRD selection rule needs this later: the AOT host can say "not available in this build" and name the alternative. In this change all real entries are AllHosts. A test source registers an Only DotnetTool entry to cover the requirement. Rule for later steps: an entry for one host is declared in shared code, and only its implementation is bound in that host's composition.

CLI-1. extension list becomes a hosted command; strings exist only at the output edge

ManagementScenario keeps the static extension command for install, use, remove and which, and adds list to it as a subcommand built from the service provider. If the builder cannot add a hosted subcommand to a static parent, the scenario builds the whole extension command through AddCommand(Func<IServiceProvider, Command>); the four other subcommands do not change.

ExtensionListCommand keeps --platform and --local (they apply to installed extensions, and none exist before PRD step 3) and adds --json. ExtensionListReport.From(ExtensionCatalog) is the one place that turns typed values into text. It reads ToString() and the WireValue members, so it has no switch on an F# union. The report record is a serialization shape only. No code parses it back or makes decisions from it.

A source-generated ExtensionListJsonContext in C# (camelCase, indented, description left out when absent) serializes the report. The member names inside capabilities.backend are the MEP wire names. A failure writes {"host", "extensions": [], "diagnostics": [{"code", "message"}]} with --json, or one line on stderr without it, and exits 2.

Alternative: a new morphir extension info command (the PRD names list; one command is enough).

PLG-1. The pipeline plugins are not registered in this change

The PRD lists the plugins in src/Morphir.IR.Pipeline.Plugins as first built-ins. They are not registered here, because no CLI command runs them: Morphir.Tooling does not reference that project, and the plugins are a library API (Plugin<'T>) used inside the F# generator. An entry with a validator or transform capability that no command can run would be a false claim. PRD step 1 registers TypeValidator as a Validator capability when the in-process validator contract and its command exist. The PRD is updated with this decision (task 9.1).

CLN-1. Remove the unused list records

Remove ExtensionList, ExtensionListResult, ExtensionInfo and ExtensionHandlers.HandleList from Features/Management/. They have no callers, and ExtensionInfo would be confused with the MEP record. The install, use, remove and which records stay until PRD step 3.

TST-1. Tests

  • Parsers (tests/Morphir.Extensions.Tests, Expecto and FsCheck): for each parsed type, properties that every generated valid text parses and prints back unchanged, and tests for each ParseFailure case. The ExtensionId tests include the upstream examples, dotted ids, and ., .., a..b, .a, a., A, 1a, a- and 239 characters. A test calls Create for every literal in source code.
  • Registry (same project): types derived from capabilities, IsAvailableIn, ordinal order, and DuplicateIds naming every duplicate.
  • Interop (tests/Morphir.Tooling.Tests, TUnit, C#): TryParse and TryCreate from C# with nullable flow, and a compile-time check that passing null to a non-nullable F# parameter is an error (a project that is expected to fail to build, or a Roslyn test).
  • Generation (GEN-1): the existing generate tests and contract scripts pass unchanged. A new test checks that a malformed --target (for example C#) gives the same unknown-target diagnostic as an unknown well-formed target.
  • Agreement: every registered backend has an entry, and every backend target in the registry resolves through RegisteredBackendResolver for at least one declared model.
  • Executables (tests/Morphir.E2E.Tests): a feature that runs extension list --json and parses stdout. Today the locator finds only the morphir executable. Add a tool executable type that runs the built dotnet-morphir, run the feature for both, and compare the shared entries.
  • The AOT publish keeps zero new trim and AOT warnings, including from Morphir.Extensions.

Migration plan

No data migration. The change is additive apart from extension list, which was a not-implemented command. Rollback: revert the change.

Open questions

C# 15 union types. After .NET 11 is generally available, a separate change can decide whether the C# edge uses C# 15 union or closed types. That would not change these decisions: the domain stays F# (LANG-1). It would only change how C# code consumes F# unions where a Match member exists now.

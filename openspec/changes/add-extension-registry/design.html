Context

See proposal.md for the reason. The requirements are in specs/extension-registry/spec.md. The current state:

  • One composition, two hosts. src/Morphir/Program.cs builds the CLI with MorphirCli.CreateBuilder(...).AddScenario<...>(). dotnet-morphir (src/Morphir.Tool/Program.cs) calls Morphir.Program.Main(args), so the two hosts cannot tell themselves apart today. VersionInfo is internal to each entry assembly, so Morphir.Tooling cannot read the host version.
  • Backends are already static. GenerationScenario registers FSharpGenerationBackend and CSharpGenerationBackend as IGenerationBackend through TryAddEnumerable. Each has a BackendDescriptor with Identity (morphir.csharp, morphir.fsharp), Target and per-family BackendCapability version sets. RegisteredBackendResolver selects from the same set.
  • The extension command is static. ManagementScenario.CreateExtensionCommand() builds it with no service provider. HandleExtensionList prints two fixed lines. The records in Features/Management/ExtensionCommands.cs and ExtensionHandlers.HandleList have no callers.
  • Hosted commands exist. MorphirCliBuilder.AddCommand(Func<IServiceProvider, Command>) builds a command after the container is built. GenerateCommand uses it.
  • MEP shape. The MEP contract (spec/mep/contract/src/mep.gleam in finos/morphir, 0.2.0-draft.1) defines ExtensionInfo { id, name, version, description?, types, author?, homepage?, license?, min_sdk_version? }, ExtensionType with the wire values frontend, backend, transform, validator, workspace, and BackendCapability { targets, ir_versions, generate }.
  • Constraints. The morphir executable is Native AOT and trimmed. No reflection-based discovery, no assembly loading. JSON uses source-generated contexts. Stdout carries command output only.

Goals and non-goals

Goals: registry and generation contracts in which invalid values cannot be constructed (TYP-1); one registry type that the later PRD steps extend (configured extensions in step 2, installed extensions in step 3) without a change to its shape; one source of truth for generator identity, shared with generate; a host identity that both hosts set explicitly.

Non-goals: the selection rule; a change to RegisteredBackendResolver behavior (its inputs become typed, GEN-1); MEP wire types or JSON-RPC; any external runtime; registration of the pipeline plugins (PLG-1).

Decisions

TYP-1. Parse, don't validate: every domain value is a parsed type

No registry or generation contract holds a raw string, a C# enum or a flag that must be checked later. Each value has one of two shapes:

  • Parsed value: a sealed class with a private constructor, static Parsed<T> Parse(string text) for untrusted text, and static T Create(string literal) for literals in source code. Create throws on invalid text, and a unit test calls it for each literal. ToString() gives the canonical text, which only the output edge uses. Equality and ordering are ordinal on the canonical text.
  • Closed union: an abstract record with a private constructor and sealed nested cases, as AGENTS.md section 6 shows. The handlers use exhaustive switch expressions.

Not readonly record struct, because default(T) skips the constructor and holds null. Not enum, because any integer converts to it.

public abstract record Parsed<T>
{
    private Parsed() { }
    public sealed record Valid(T Value) : Parsed<T>;
    public sealed record Invalid(ParseFailure Failure) : Parsed<T>;
}

public abstract record ParseFailure            // rendered to a diagnostic code at the output edge
{
    private ParseFailure() { }
    public sealed record Empty(string Field) : ParseFailure;
    public sealed record TooLong(string Field, int Limit) : ParseFailure;
    public sealed record InvalidCharacter(string Field, int Index) : ParseFailure;
    public sealed record InvalidSegment(string Field, int Segment) : ParseFailure;
    public sealed record InvalidVersion(string Field, Versioning.ParseError Error) : ParseFailure;
}

REG-1. Registry types in the shape of MEP, mapped to Morphir.Mep later

public abstract record MorphirHost             // Native: "morphir"; DotnetTool: "dotnet-morphir"
{ private MorphirHost() { } public sealed record Native : MorphirHost; public sealed record DotnetTool : MorphirHost; }

public sealed record HostIdentity(MorphirHost Host, ReleaseVersion Version);

public abstract record HostAvailability        // an empty host set cannot exist
{ private HostAvailability() { } public sealed record AllHosts : HostAvailability; public sealed record Only(MorphirHost Host) : HostAvailability; }

public abstract record ExtensionDelivery       // Process(...) and Wasm(...) carry their own data in later steps
{ private ExtensionDelivery() { } public sealed record BuiltIn : ExtensionDelivery; }

public abstract record ExtensionType           // MEP wire values frontend, backend, transform, validator, workspace
{ private ExtensionType() { } public sealed record Frontend : ExtensionType; public sealed record Backend : ExtensionType;
  public sealed record Transform : ExtensionType; public sealed record Validator : ExtensionType; public sealed record Workspace : ExtensionType; }

public sealed record BackendClaim(NonEmptySet<TargetId> Targets, NonEmptySet<SourceFormatVersion> IrVersions);

public abstract record ExtensionCapability     // more cases in later steps; each case fixes its type
{
    private ExtensionCapability() { }
    public sealed record Backend(BackendClaim Claim) : ExtensionCapability;
    public ExtensionType Type => this switch { Backend => new ExtensionType.Backend(), _ => throw new UnreachableException() };
}

public sealed record ExtensionIdentity(ExtensionId Id, ExtensionName Name, ReleaseVersion Version, ExtensionDescription? Description);

public sealed record ExtensionEntry(ExtensionIdentity Identity, ExtensionDelivery Delivery, HostAvailability Hosts,
    NonEmptySet<ExtensionCapability> Capabilities)
{
    public NonEmptySet<ExtensionType> Types => Capabilities.Map(capability => capability.Type);   // derived, never stored
    public bool IsAvailableIn(MorphirHost host) => Hosts switch
    { HostAvailability.AllHosts => true, HostAvailability.Only only => only.Host == host, _ => throw new UnreachableException() };
}

What the types rule out:

  • An entry with no types. A capability is required, so there is always at least one type.
  • Types that disagree with the claims. Types come from the claims.
  • An entry for no host.
  • A backend claim with no target or no IR version.
  • A generate flag set to false on a backend claim. Generation is the only backend operation in MEP, so the output edge writes generate: true for every backend claim.

The identity holds only the MEP members that a built-in fills now. author, homepage, license and min_sdk_version come with parsed types when a step needs them. Delivery, hosts and availability are morphir-dotnet additions. They never go on the MEP wire.

When Morphir.Mep lands (PR #495), add one mapping from these types to the MEP ExtensionInfo and ExtensionCapabilities, and one parser from MEP messages into them. Do not replace the registry types: they carry the additions and the invariants.

Alternatives: string records validated by the registry (the earlier draft; the checks move away from the data, and an invalid entry can exist); wait for Morphir.Mep (this blocks step 0 on PR #495, which the PRD rules out); reuse Features/Management.ExtensionInfo (it models installed versions, not identity).

REG-2. Static registration through IExtensionSource; the catalog cannot hold a duplicate

public interface IExtensionSource { IEnumerable<ExtensionEntry> Entries { get; } }

public sealed class ExtensionCatalog
{
    private ExtensionCatalog(HostIdentity host, ImmutableSortedDictionary<ExtensionId, ExtensionEntry> entries) { … }
    public HostIdentity Host { get; }
    public ImmutableSortedDictionary<ExtensionId, ExtensionEntry> Entries { get; }   // ordinal order by id
    public static Built Create(HostIdentity host, IEnumerable<ExtensionEntry> entries);
}

public abstract record Built                    // the result of Create
{ private Built() { } public sealed record Catalog(ExtensionCatalog Value) : Built;
  public sealed record Failed(RegistryError Error) : Built; }

public abstract record RegistryError
{ private RegistryError() { } public sealed record DuplicateIds(NonEmptySet<ExtensionId> Ids) : RegistryError; }

ExtensionRegistry reads every IExtensionSource and the HostIdentity from the container, and calls ExtensionCatalog.Create. A catalog value always has unique ids, so no later code checks for them. The command maps DuplicateIds to the code extension.duplicate_id and exit code 2, and names every duplicate id.

Alternatives: assembly scanning or MEF (not AOT-safe, and the PRD forbids it); attributes plus a source generator (more than two built-ins need; it can come later without a change to IExtensionSource); a static list in Program.cs (it drifts from the backend registrations).

REG-3. Backend entries come from the registered backends

BackendExtensionSource takes IEnumerable<IGenerationBackend> and makes one entry for each backend. It does no parsing: BackendDescriptor already holds parsed values (GEN-1).

  • Identity: Descriptor.Id, Descriptor.Name, Descriptor.Description, and the host's ReleaseVersion.
  • Delivery BuiltIn, hosts AllHosts.
  • One capability, Backend(new BackendClaim(NonEmptySet.Create(Descriptor.Target), union of capability versions)).

The two backends declare ExtensionId.Create("morphir.csharp") and ExtensionId.Create("morphir.fsharp"), with the names "C# generator" and "F# generator". The list and generate share one source of truth, and a test checks that they agree.

GEN-1. The generation contracts hold parsed values

The registry reads the generation contracts, so those contracts become parsed types in this change:

ContractTodayAfter
TargetIdreadonly record struct TargetId(string Value)Parsed value (TYP-1), with the ExtensionId grammar
BackendCapability.VersionsImmutableHashSet<string>NonEmptySet<SourceFormatVersion>; Supports compares model.Version by value, so the exact declared spelling still decides the match
BackendDescriptor.IdentitystringExtensionId Id, plus ExtensionName Name and ExtensionDescription? Description
BackendDescriptor.CapabilitiesImmutableArray<BackendCapability>NonEmptySet<BackendCapability>

generate behavior does not change. CliGenerationSettingsResolver parses --target with TargetId.Parse. A parse failure gives the same unknown-target invocation failure, with the same message and list of available targets, as a well-formed unknown target does today. The backend report field is ExtensionId.ToString(), so it is still morphir.csharp or morphir.fsharp. The existing generate tests and the PowerShell contract scripts run unchanged and pass.

ModelDescriptor, SourceFormatVersion and the option parsing are already typed, and they do not change.

ID-1. Extension ids may contain dots, as a documented superset of upstream

The upstream rule (crates/morphir-distribution/src/domain/identity.rs in finos/morphir-rust) allows one lowercase portable token: [a-z]([a-z0-9-]*[a-z0-9])?, at most 238 characters. It refuses morphir.csharp. morphir-dotnet accepts one or more such tokens joined by dots (decided 2026-11-07). This keeps the published backend identities, and a namespace prefix such as morphir. stays possible.

Each segment follows the upstream token rule, so an id still has no empty segment, no . or .. segment, and no leading or trailing dot. Ids stay portable as file names: morphir.csharp.json is valid on every supported platform. Until upstream accepts dots, a dotted id is a morphir-dotnet extension. Built-ins never go into the upstream store, so step 0 is not affected. PRD step 3 must refuse to write a dotted id into the shared upstream store or locks until upstream accepts it. The closeout of this change sends the proposal upstream (task 8.2).

Alternatives: rename to morphir-csharp everywhere (this breaks the published backend report field); keep two identities, one for the extension and one for the backend (one backend would have two names).

HOST-1. Each entry point states its host

// src/Morphir/Program.cs
public static int Main(string[] args) => Run(args, new HostIdentity(new MorphirHost.Native(), ReleaseVersion.Create(VersionInfo.Version)));
public static int Run(string[] args, HostIdentity host) { /* existing body; registers host as a singleton */ }

// src/Morphir.Tool/Program.cs
private static int Main(string[] args) =>
    Morphir.Program.Run(args, new HostIdentity(new MorphirHost.DotnetTool(), ReleaseVersion.Create(VersionInfo.Version)));

VersionInfo.Version comes from the build (0.0.0-dev when no version is set). ReleaseVersion.Create throws at start if the build writes a value that is not SemVer. A build test runs --version and parses the output, which catches this before release. If PR #495 has landed when this change is applied, add HostIdentity to its CreateApp(string[] args, Action<MorphirCliBuilder> extend) seam instead of adding Run. --version stays as it is.

Alternatives: read RuntimeFeature.IsDynamicCodeSupported (true for a JIT test run of the morphir project, so it reports the wrong host); read the process name (it is dotnet when the tool runs as dotnet dotnet-morphir.dll).

HOST-2. Entries declare their hosts; availability is computed

A host lists every entry it knows, including entries for the other host only, and marks those as not available. The PRD selection rule needs this later: the AOT host can say "not available in this build" and name the alternative. In this change all real entries are AllHosts. A test source registers an Only(DotnetTool) entry to cover the requirement. Rule for later steps: an entry for one host is declared in shared code (Morphir.Tooling), and only its implementation is bound in that host's composition.

CLI-1. extension list becomes a hosted command; strings exist only at the output edge

ManagementScenario keeps the static extension command for install, use, remove and which, and adds list to it as a subcommand built from the service provider. If the builder cannot add a hosted subcommand to a static parent, the scenario builds the whole extension command through AddCommand(Func<IServiceProvider, Command>); the four other subcommands do not change.

ExtensionListCommand keeps --platform and --local (they apply to installed extensions, and none exist before PRD step 3) and adds --json. ExtensionListReport.From(ExtensionCatalog) is the one place that turns typed values into text, through each type's ToString() and exhaustive switch mappings for the unions. The report record is a serialization shape only. No code parses it back or makes decisions from it.

$ morphir extension list

morphir.csharp  C# generator   0.4.0     backend   built-in   morphir, dotnet-morphir
morphir.fsharp  F# generator   0.4.0     backend   built-in   morphir, dotnet-morphir
{
  "host": "morphir",
  "extensions": [
    {
      "id": "morphir.csharp",
      "name": "C# generator",
      "version": "0.4.0",
      "types": ["backend"],
      "delivery": "built-in",
      "hosts": ["morphir", "dotnet-morphir"],
      "available": true,
      "capabilities": {
        "backend": { "targets": ["csharp"], "irVersions": ["1", "2", "3", "3.0.0", "3.1.0", "4", "4.0.0"], "generate": true }

A source-generated ExtensionListJsonContext (camelCase, indented, description left out when absent) serializes the report. The member names inside capabilities.backend are the MEP wire names. A failure writes {"host", "extensions": [], "diagnostics": [{"code", "message"}]} with --json, or one line on stderr without it, and exits 2.

Alternative: a new morphir extension info command (the PRD names list; one command is enough).

PLG-1. The pipeline plugins are not registered in this change

The PRD lists the plugins in src/Morphir.IR.Pipeline.Plugins as first built-ins. They are not registered here, because no CLI command runs them: Morphir.Tooling does not reference that project, and the plugins are a library API (Plugin<'T>) used inside the F# generator. An entry with a validator or transform capability that no command can run would be a false claim. PRD step 1 registers TypeValidator as a Validator capability when the in-process validator contract and its command exist. The PRD is updated with this decision (task 8.1).

CLN-1. Remove the unused list records

Remove ExtensionList, ExtensionListResult, ExtensionInfo and ExtensionHandlers.HandleList from Features/Management/. They have no callers, and ExtensionInfo would be confused with the MEP record. The install, use, remove and which records stay until PRD step 3.

TST-1. Tests

  • Parsers (tests/Morphir.Tooling.Tests/Features/Extensions/): for each parsed type, property tests that every generated valid text parses and prints back unchanged, and table tests for each ParseFailure case. The ExtensionId tests include the upstream examples, dotted ids, and ., .., a..b, .a, a., A, 1a, a- and 239 characters. A test calls Create for every literal in source code.
  • Registry: backend adapter mapping, ordinal order, DuplicateIds naming every duplicate, availability for an Only entry, and types derived from capabilities.
  • Generation (GEN-1): the existing generate tests and contract scripts pass unchanged. A new test checks that a malformed --target (for example C#) gives the same unknown-target diagnostic as an unknown well-formed target.
  • Agreement: every registered backend has an entry, and every backend target in the registry resolves through RegisteredBackendResolver for at least one declared model.
  • Executables (tests/Morphir.E2E.Tests): a feature that runs extension list --json and parses stdout. Today the locator finds only the morphir executable. Add a tool executable type that runs the built dotnet-morphir, run the feature for both, and compare the shared entries.
  • The AOT publish keeps zero new trim and AOT warnings.

Risks and trade-offs

RiskMitigation
PR #495 changes Morphir.Program at the same time (CreateApp).HOST-1 names both paths. The change is a few lines in each entry point.
GEN-1 touches generation code that is already released.The output and diagnostics stay the same, and the existing tests and contract scripts run without change. The new malformed-target test pins the one new code path.
Dotted ids are not valid upstream yet (ID-1).Built-ins never enter the upstream store. PRD step 3 refuses dotted ids in shared upstream files until upstream accepts them. The upstream proposal is a closeout task.
Create throws for an invalid literal at run time, not at compile time.Literals are few and fixed. A unit test calls each one, so CI catches a bad literal before release. An analyzer or source generator can move this to compile time later.
A build that writes a non-SemVer VersionInfo.Version would stop the host at start.The build test parses --version output with the same parser.
The registry types drift from MEP when Morphir.Mep lands.The types copy MEP names and wire values. One mapping, one parser and a round-trip test come with Morphir.Mep.
Scripts that read the old stub text ("No extensions installed.") break.The stub never listed anything. Record the output change in the release notes and the CLI documentation.
The E2E run of dotnet-morphir needs the tool build in CI.Use the build output of Morphir.Tool (dotnet dotnet-morphir.dll), not a packed tool install.

Migration plan

No data migration. The change is additive apart from the extension list output, which was a stub. Rollback: revert the change.

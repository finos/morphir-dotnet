# Task 4.2: the runtime availability report

Date: 10 November 2026. Machine: Windows 11 on ARM64. Pin: finos/morphir `8b3c4c35`.

## What the task asks, and the result

"Verify a host started without its engine library reports `engine_missing`, fails a WASM command by name
and still runs commands that need no WASM."

The end-to-end tests copy a built executable's folder into a sandbox, delete every engine library from
the copy and run the copy. Results per executable:

| Executable | `extension runtimes --json` | `extension worker` | `--version`, `--help`, `extension list --json`, `ir verify --json` |
| --- | --- | --- | --- |
| `dotnet-morphir` | unavailable, `engine_missing` | `refused` `extension.runtime_unavailable`, no stdout, exit 3 | succeed |
| managed `morphir` | the same | the same | succeed |
| framework-dependent build of `src/Morphir` | the same | the same | succeed |
| Native AOT `morphir` (`win-arm64`, `wasmtime.dll` removed) | the same | the same | succeed |

Before the change the worker in such a copy crashed with an unhandled `System.DllNotFoundException`.

The unmodified executables report the runtime as available:

```json
{"host":"morphir","platform":"win-arm64","runtimes":[{"kind":"wasm","available":true,
 "engine":{"name":"wasmtime","version":"50.0.1"},"profiles":["extism-kernel-v1"],
 "bounds":{"memoryBytes":268435456,"deadline":"enforced","budget":"enforced"}}]}
```

## How a reason is decided

| Reason | When |
| --- | --- |
| `platform_unsupported` | The platform is not one of the six the Wasmtime package ships a native library for. The engine is not started. |
| `engine_missing` | Starting the engine threw `DllNotFoundException` and no library file is present. |
| `engine_load_failed` | Any other failure, or `DllNotFoundException` while the file is present. A text file named `wasmtime.dll`, and an x64 library on ARM64, both give this reason. |
| `disabled` | Never produced. See below. |

The probe runs at most once in a process and only on first need: `extension runtimes`, the module
loader, and `extension list` for a `wasm` entry. Tests show it does not run for the CLI's composition,
for `extension list` with only built-in entries, or for the worker's help and argument checks.

## Native AOT

The Native AOT publish for `win-arm64` has the branch's 27 IL warnings, 24 in `Morphir.Core` JSON
converters and three assembly summaries, and no new one. Nothing is suppressed.

## What is not met as written, and why

1. **The report has no `deployment` member, and the failure names the host in place of the offering.**
   The spec asks the failure to name "the offering, the platform and the reason". Nothing at run time
   says which offering an executable is: `HostIdentity` holds the host kind and the version, and the
   Native AOT and the managed `morphir` both report `morphir`. The change `add-deployment-and-acquisition`
   writes the deployment only into a build-side file. What would supply it: each release profile writing
   its offering into a generated constant, as the version is generated today, and `HostIdentity` carrying
   it. Until then the message reads, for example, `dotnet-morphir 0.4.0-alpha.3 on win-arm64`. This is
   the limit the task's note expected.
2. **The pinned contract has no `extension.runtime_unavailable` among a worker's refusal codes.** It
   lists four. The .NET spec requires the code. The worker reports one `refused` event with the code and
   exits with 3, which is the contract's status for a refusal before any request. The question is with
   the parent.
3. **Nothing can disable the runtime.** The spec lists `disabled` as a reason and defines no switch. The
   reason exists in the type and the documentation and is never produced.

## For packaging (group 5)

- A framework-dependent application starts when a native file its `deps.json` lists is missing, and the
  Native AOT `morphir` loads `wasmtime.dll` on first need, so both start without the engine.
- A portable build carries all six engine libraries, about 140 MB.
- On musl the report says `platform_unsupported`, from the platform check.

## After the parent's answer (938f798)

10 November 2026. The parent answered the three points under "What is not met as written" at
finos/morphir `938f798`, and the pin moved there. All three are settled:

1. **The offering.** The parent dropped the offering from the requirement "Unavailable runtime fails by
   name", which now names the host, the platform and the reason, and from the runtime report. The report
   keeps no `deployment` member, and the failure's message already names the host.
2. **The code.** `extension.runtime_unavailable` is now in the contract, among the worker's refusals, with
   the worker rule `start-order`. The worker's behaviour did not change. The contract reader now requires
   the worker refusals to be exactly the worker's two codes and holds the rule's text, and a test checks
   that every code a `refused` event can carry is in the contract.
3. **`disabled`.** The parent dropped the reason and the switch. The reason is removed from
   `WasmRuntimeUnavailableReason`, the tests and the documentation, and the host reports three reasons.

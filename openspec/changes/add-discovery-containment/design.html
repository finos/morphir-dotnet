Context

See proposal.md for the motivation and specs/discovery-containment, specs/morphir-project-system and specs/configuration-resolution for the required behavior.

Current state that shapes the approach:

  • Each native host computes its own boundary: invocation.Boundary ?? Path.GetPathRoot(start). This is repeated in ConfigurationInspectionHost, ConfigurationEditingHost and ProjectMigrationHost. NativeWorkspaceMigrationHost uses its directory as the boundary and has no outer bound.
  • Environment snapshot: the config commands capture it once (Environment.GetEnvironmentVariables) and pass it explicitly. Shared discovery and resolution never read process state, and the specs require that.
  • Isolation: --isolated is a plain Option<bool> on the two config commands. The migration services already exclude machine and personal sources by construction.
  • The global home is discovered as a project: DiscoveryRequest carries only StartPath and Boundary, so the upward walk can't tell that <home>/.morphir/morphir.toml is the global file. Verified in a sandbox: that file loads as both Global and RootPrimary.
  • Native Windows MORPHIR_HOME: MachineLocations tests ProjectPath.isAbsolute on the raw value before normalizing it, so C:\… is joined onto the start directory.
  • Legacy discovery: the legacy WorkspaceDiscovery, ConfigResolver and TomlParser in Morphir.Tooling/Configuration are used only by their own tests and by a DI registration in ManagementScenario, whose commands are not implemented.
  • Test runner parallelism: TUnit and Expecto run tests in parallel and nothing throttles child processes. Many step classes start dotnet children with a 30-second timeout. On timeout they kill without waiting and then delete the child's working directory.

Goals and non-goals

Goals:

  • One implementation of the containment rules, shared by every discovering command.
  • Containment that a parent process can impose on any Morphir child through the environment alone.
  • Test suites that read and write nothing outside their own sandbox, and that fail loudly if they do.

Non-goals:

  • Wiring the dist, tool and extension commands (#490, #491, #492).
  • Relocating the artifact root of ArtifactPathResolver, which still uses OsPaths.
  • Removing the F# configuration types in Morphir.Configuration (Types.fs, Merge.fs, CiDetection.fs). They ship in a different package and are not the removed entry point.
  • Changing the in-process console redirection in MorphirCli.CreateBuilder.

Decisions

CTL-1. One containment resolver in the CLI layer

Add a pure Containment.Resolve(flagBoundary, flagIsolated, environment, currentDirectory) in Morphir.Tooling. It returns either the effective boundary and isolation together with their sources (flag, MORPHIR_DISCOVERY_BOUNDARY/MORPHIR_ISOLATED, or default), or a typed usage failure. Every host takes its values from it instead of computing ?? GetPathRoot itself.

  • A relative value resolves against the current directory.
  • Values go through Path.GetFullPath and then ProjectPath.normalize, so native separators, drive paths and UNC paths all work.
  • An empty variable counts as unset.

Alternatives considered:

  • Interpreting the variables in each command: rejected, because it duplicates the rules four times.
  • Putting the resolver in Morphir.Configuration: rejected, because the shared libraries must not read ambient process state, and choosing which variable names apply is CLI host policy. Library hosts already pass boundaries explicitly.

CTL-2. --isolated takes an optional value, and an absent flag defers to the environment

The option keeps its name and stays boolean, with arity zero-or-one, so both --isolated and --isolated false parse. Whether the flag was given comes from the parse result (GetResult(option) is null), not from its value. That is what lets an absent flag fall back to MORPHIR_ISOLATED. MORPHIR_ISOLATED accepts true/false/1/0, ignoring case. Any other value is a usage failure (exit 2) that names the variable and the accepted values.

Alternative considered: a separate --no-isolated flag. Rejected, because the CLI has no other negated-flag pairs, and an optional value is the System.CommandLine idiom.

CTL-3. Validate containment in the command action, before any host I/O

Resolution and the start-path check (the directory, for workspace migrate) run at the top of each command action. A failure returns the command's normal report with a discovery.boundary or usage diagnostic and exit code 2, and no host is constructed. The help action never reaches the command action, so help does no I/O and ignores invalid variables. The diagnostic names the boundary's source, so a user can see that an inherited MORPHIR_DISCOVERY_BOUNDARY is the cause.

workspace migrate gains --discovery-boundary as an outer bound. Its directory is still the authorization root for the inventory.

CTL-4. Reserved names

Add MORPHIR_DISCOVERY_BOUNDARY and MORPHIR_ISOLATED to EnvironmentMapping.reserved. Without this, the existing mapping would turn them into the configuration keys discovery_boundary and isolated.

DISC-1. Discovery receives the Morphir home explicitly and skips primaries located in it

Extend the discovery request with an optional Morphir home directory, so discovery still reads no ambient state. While walking upward, discovery skips any primary candidate whose file sits directly in that directory:

  • For the default home, that is <home>/.morphir/morphir.<ext>, reached through the .morphir/ layout.
  • For a relocated MORPHIR_HOME=/opt/h, that is /opt/h/morphir.<ext>.

Native hosts compute the home from the same environment snapshot (nonempty MORPHIR_HOME, otherwise HOME/USERPROFILE plus .morphir), even when isolated. Isolation removes global sources but must not turn the global file back into a project. In-memory and library callers that pass no home keep today's behavior.

Alternatives considered:

  • Skipping every .morphir directory directly under any home directory: rejected, because it is over-broad and needs platform knowledge inside discovery.
  • Renaming the global file: rejected, because it breaks existing global configuration.

DISC-2. Normalize MORPHIR_HOME before testing whether it is absolute

In MachineLocations, normalize the value, mapping separators the way ProjectPath.normalize does, before calling ProjectPath.isAbsolute. Relative values keep resolving against the start directory, which the spec now states explicitly. The same normalized home feeds DISC-1.

LEG-1. Delete the legacy discovery and resolver

Remove the following from Morphir.Tooling/Configuration:

  • WorkspaceDiscovery.cs, ConfigResolver.cs and TomlParser.cs.
  • Their tests: WorkspaceDiscoveryTests, ConfigResolverTests and TomlParserTests.
  • The services.AddSingleton<WorkspaceDiscovery>() registration in ManagementScenario.

OsPaths and its tests stay, because ArtifactPathResolver uses them. The spec delta removes the compatibility requirement, and the CHANGELOG records the API removal as BREAKING.

TEST-1. A shared C# test-support project

Add a non-packable tests/Morphir.TestSupport project. The C# test projects reference it (Tooling, E2E, Build, Myriad.Integration), and so can the F# test projects that start processes. It provides:

  • TestSandbox: a disposable temp root created with Directory.CreateTempSubdirectory("morphir-test-"), containing home/, appdata/, localappdata/, programdata/, xdg-config/, xdg-cache/ and work/.
  • ChildProcess: a runner (TEST-2, TEST-3).
  • TolerantDirectory.Delete, generalized from the helper already in LocalInstallationTests.

Alternative considered: extending the F# src/Morphir.Testing. Rejected, because it is a generation-conformance library under src/, and the E2E and Build test projects can't take product references.

TEST-2. A process-wide concurrency gate for child processes

In each test process, ChildProcess acquires a static semaphore before it starts a child. The default limit is max(2, ProcessorCount / 2), which MORPHIR_TEST_MAX_PROCESSES overrides. The timeout starts only once the gate is held, so queueing no longer eats a test's 30-second budget. This tackles the root cause of the timeouts rather than raising them.

Alternatives considered:

  • TUnit [ParallelLimiter] on classes: rejected, because it doesn't reach Reqnroll-generated feature classes cleanly, and it can't limit helpers shared across classes.
  • [NotInParallel] everywhere: rejected, because it makes the suite too slow.

TEST-3. Child processes are always awaited before cleanup

ChildProcess reads stdout and stderr concurrently and applies the timeout. On timeout or cancellation it calls Kill(entireProcessTree: true), then waits for exit (bounded) and for both reader tasks, before it throws a timeout error that includes the captured output. Process objects are disposed.

Fixture cleanup uses TolerantDirectory.Delete: retries with backoff, then logs and never throws. Fixtures that deliberately keep recovery evidence (.morphir-edit-* journals) keep that behavior. dotnet build/run children pass -nodeReuse:false and set MSBUILDDISABLENODEREUSE=1, so no MSBuild node outlives the test holding its directory.

TEST-4. The sandbox environment contains Morphir, not the SDK

TestSandbox.Apply(ProcessStartInfo) configures the child environment:

  • Points HOME, USERPROFILE, APPDATA, LOCALAPPDATA, PROGRAMDATA, XDG_CONFIG_HOME and XDG_CACHE_HOME into the sandbox.
  • Sets MORPHIR_HOME to home/.morphir and removes every other inherited MORPHIR_* variable.
  • Sets MORPHIR_DISCOVERY_BOUNDARY to the sandbox root and, by default, MORPHIR_ISOLATED=1. Tests that exercise machine sources opt out and write their machine files inside the sandbox instead.
  • Pins NUGET_PACKAGES to the real global packages folder, resolved before the override, so dotnet run/build keep using the warm cache.
  • Gives DOTNET_CLI_HOME a sandbox directory, with DOTNET_NOLOGO=1 and DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1.
MORPHIR_HOME=<sandbox>/home/.morphir
MORPHIR_DISCOVERY_BOUNDARY=<sandbox>
MORPHIR_ISOLATED=1
NUGET_PACKAGES=<real global packages folder>

TEST-5. No shared mutable state between scenarios

  • Morphir.E2E.Tests SharedSteps stores its execution result in ScenarioContext instead of a [ThreadStatic] field.
  • ArtifactPathResolverTests uses the isolating constructor, with its global root in the sandbox.
  • Repo-relative discovery in test helpers uses AppContext.BaseDirectory instead of the current directory.
  • Manual AOT publishes go to a sandbox directory, not artifacts/test-builds, and run [NotInParallel] with a timeout.

TEST-6. A tripwire for leaks onto the machine

Each process-heavy test assembly takes a snapshot of the real machine's Morphir locations (~/.morphir, %APPDATA%\Morphir, %APPDATA%\morphir, $XDG_CONFIG_HOME/morphir) before the run and compares it after. The snapshot records whether each exists and the newest write time of its entries. The assembly fails if the run created or modified any of them, so a future test that escapes its sandbox is caught in CI, where those directories normally don't exist.

Alternative considered: pointing the whole CI test job at a fake HOME. Rejected, because it would also relocate the NuGet and SDK state the build needs, and it would not catch leaks on developer machines.

Risks and trade-offs

RiskMitigation
An inherited MORPHIR_DISCOVERY_BOUNDARY or MORPHIR_ISOLATED silently changes a user's results.Diagnostics name the source of a boundary failure, and config path --json reports the effective controls and their sources (CTL-3). Both variables are documented with the other MORPHIR_* variables.
Removing ConfigResolver/WorkspaceDiscovery breaks an unknown caller.No restorable release ever shipped them. The CHANGELOG marks the removal BREAKING and names the replacement entry points.
Skipping primaries in the Morphir home hides a deliberate project rooted at the home directory.Only files located directly in the Morphir home directory are skipped. A morphir.toml placed directly in the user's home directory still works.
The concurrency gate lengthens the test run.The default is half the cores and can be tuned with MORPHIR_TEST_MAX_PROCESSES. Fewer timeouts and reruns offset the cost.
Redirecting HOME breaks dotnet children (NuGet, workloads, first run).NUGET_PACKAGES is pinned to the warm cache and DOTNET_CLI_HOME gets its own sandbox directory (TEST-4). Children that need the real SDK state opt out of the home redirect, but keep the boundary and isolation.
The tripwire flags a write made by a tool outside the test run, during the run.It only checks Morphir-owned directories and reports exactly which paths changed.

Migration plan

  1. Land as one PR before tagging v0.4.0-alpha.1, after #489 merges.
  2. Update the CHANGELOG:
    • Added: the two environment variables and the optional --isolated value.
    • Fixed: the global home is no longer discovered as a project, and native Windows MORPHIR_HOME works.
    • Removed (BREAKING): the legacy Morphir.Tooling resolver and discovery.
  3. Rollback is a revert of the PR. No on-disk formats or configuration files change.

Context

The runtime is src/Morphir.SDK, an F# net10.0 package. Dict.union currently favors the second dictionary; independent Python tests favor the first. tests/Fixtures already holds shared IR and Ion data. No SDK conformance main spec exists. This change adds a bounded contract and evidence, not runtime corrections.

Goals and non-goals

Establish reviewable evidence, admitted behavior, representation limits and a stable fixture interface for both runtime workers. Exclude a complete SDK audit, a new execution framework, runtime changes and new language toolchains at test runtime.

Decisions

LAND-1. Squash-aware landing and cleanup

Prefer squash merging for initiative and archival PRs unless PR instructions or repository settings select another method. Record the actual method, the distinct final submitted head SHA and the hosting service's recorded landed SHA. Verify that the exact PR is merged into main and its landed commit is reachable from refreshed main. Original worker commits need not remain ancestors of main after a squash. Successors use main with the landed SHA. Before cleanup, verify a clean owned worktree and HEAD matching its last submitted PR head with no extra local commits; git branch --merged is not landing proof for a squash.

CONF-1. Pin evidence and preserve its meaning

Use exact upstream commits and licenses in a PROVENANCE.md and a small inventory.json. The initial baseline covers Basics arithmetic/comparison and Order; List construction, map, append, head, tail and length; Maybe and Result constructors, map and chaining; Dict construction, lookup, update, removal, ordered conversion and union; Set construction, update, ordered conversion and union. Scalar cases cover admitted integer, double, decimal, character and string values. Admit only operations with explicit signatures, expected results or failures and a representation profile. This bounds C# SDK work without claiming all Morphir SDK modules are complete.

CONF-2. Share observations and keep adapters local

Store cases.json with schemaVersion, caseId, qualified operation, type arguments, tagged arguments, expected value/error, profile and evidence reference. Dictionaries and sets project ordered entries; decimal values use coefficient/scale or exact text; floating observations preserve exceptional values and signed zero. Higher-order cases identify a small closed set of fixture callbacks by ID, never executable host-language source. Each SDK owns its adapter. A small existing-style TUnit fixture validation project is enough; no production conformance package or generic plugin system.

CONF-3. Freeze downstream contract before dispatch

The output README and inventory freeze operation signatures, .NET numeric/text representation, arithmetic errors, ordering and compatibility classifications. This is a concrete prerequisite delivered by this worker; C# and F# workers must read it before implementation. Distinguish reference behavior, accepted .NET restrictions/extensions and existing bugs. The initial common representable domain does not imply arbitrary-precision parity or complete Unicode/decimal compatibility. Unknown or unclassified behavior fails validation.

CONF-4. Track mismatches without granting a pass

A named F# gap for first-dictionary-wins union preserves the true expected value and identifies introduce-fsharp-sdk-package as its owner. This change's tests validate evidence and classifications; they do not claim the existing SDK passes. Required conformance in each runtime's delivery cannot use skips, expected failures or rewritten expectations to hide a covered gap. Broader historical discrepancies are inventory entries outside the bounded delivery, not unbounded blocker tasks.

ORCH-1. Make the DAG executable without hidden context

orchestration.json defines exact change IDs, predecessors, ownership, readiness gates and the verified Codex target. orchestration.md and each change's handoff.md are durable context for isolated threads. Planning must be committed into a worker's base before dispatch; checked boxes alone do not establish an integrated dependency. No thread is created by these artifacts.

Thread ownership and dependency gates

This is the first implementation initiative once the planning artifacts are available on main. Start the worker checkout from main containing those merge commits, not an unmerged sibling branch.

Use the exact worker brief and coordination rules. Runtime and generation signatures come from the merged predecessor. Shared solution, package and PRD-index edits are integrated serially. The delivery lead owns only this change and its listed implementation areas. The auxiliary policy permits up to three auxiliaries per lead, sharing an initial global budget of three across at most two initiative leads. Start with one auxiliary and check CPU/memory headroom before expanding; only an explicit resource assessment and root-coordinator decision can increase the global budget. All agents use Codex gpt-6.1-sol with reasoningEffort high through T3 delegate_task, with capability discovery before each thread's first delegation and no recursive fan-out. Coordinate the one delivery-wide expensive-command slot, bound internal parallelism, and back off under resource pressure. Use disjoint writing ownership or orchestrator-created isolated worktrees with serial integration. The lead integrates results and required checks into one initiative PR; the root coordinator retains watching, landing, archive follow-up and cleanup, including auxiliary worktrees/helpers. Cancel unneeded tasks with task_cancel and follow event-driven completion without polling.

Completion requires a PR merged into main, verification of the merge commit, and removal of this initiative's clean worker worktree. An open PR or checked task list is not completion. Preserve uncommitted or unrelated work; do not remove the coordinator's checkout.

Verification

Use the scenarios in dotnet-sdk-conformance and the per-group checks in tasks.md. Follow red/green/refactor for production behavior. Test actual packaged/runtime/generated consumers where applicable; record exact toolchain versions and commands. Before contribution, run the repository-required full suite, coverage and formatting checks in addition to focused tests. No AI coauthor trailers.

Land only after the PR's required checks and reviews pass. Link created or pushed PRs through the orchestrator. If checks or reviews are pending, the root coordinator uses the PR-watch mechanism and resumes from its event; delegated children never watch PRs. Final evidence records the PR URL, head and merge SHAs, checks/reviews, confirmed main inclusion and workspace cleanup.

Risks and trade-offs

RiskMitigation
Other language runtimes disagree or expose extensionsRetain provenance and distinct applicability; choose and document the admitted contract before admitting a case.
A fixture format grows into a new frameworkUse plain tagged JSON, simple validators and a fixed callback vocabulary.
A broad audit blocks all subsequent changesFreeze the initial inventory; record the rest as explicit follow-up gaps.

Migration plan

Add fixtures and validation without altering existing runtime behavior. Rollback removes only the new corpus and documentation. This initiative drafts the umbrella PRD at docs/content/contributing/design/prds/dotnet-code-generation.md for serial coordinator integration. The coordinator maintains its status table and performs shared index updates.

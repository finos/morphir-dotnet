# Ecosystem deviations

Baseline: `finos/morphir@cde7722eb35987042a49dc646a846d693b0bd7f6`.
These entries explain the compatibility choices of the F# frontend, the
`compile` command and the F# MEP guest. They are not claims that the guest has
passed the upstream guest-kit qualification.

| Area | Recorded difference and decision | Evidence |
| --- | --- | --- |
| Compile streaming | The pinned Rust CLI implementation writes one compact report for `--json-lines`. `morphir compile --json-lines` in .NET writes the compile events and ends with a `completed` record that holds the report. Keep this visible until an upstream agreement resolves it. | [STRM-2 and follow-up](../openspec/changes/archive/2026-11-09-add-fsharp-compile/design.html#strm-2), [planned upstream follow-ups](../openspec/changes/archive/2026-11-09-add-fsharp-compile/tasks.md#workflow-follow-up) |
| MEP guest qualification | The pinned generic guest kit requires legacy 0.1 and both frontend and backend capabilities. The F# guest `morphir-fsharp-frontend` offers only the current model-tier frontend contract. It will not add legacy protocol or a backend to satisfy the older kit. | [MEP-3](../openspec/changes/archive/2026-11-09-add-fsharp-compile/design.html#mep-3), [pinned contract provenance](../tests/Fixtures/Mep/PROVENANCE.md) |
| F# backend guest qualification | The F# backend guest `morphir-fsharp-backend` offers only `morphir.backend.generateModel` with JSON tuples for IR `4.0.0` and `3.0.0`: no legacy 0.1, no `morphir.backend.generate` and no frontend. The frozen expected F# files and the shared compatibility runner adapter of `finos/morphir` do not exist yet, so the guest is not qualified with them. Its files are compared with those of the managed (JIT) built-in `morphir.fsharp`, as in `dotnet-morphir`, on the same machine, for the checked-in daily-rate and constant-folding models. The Native AOT `morphir` cannot run Fantomas and writes the same declarations unformatted, with LF line endings; the managed built-in and the guest format with Fantomas, whose line endings follow the platform (CRLF on Windows, LF elsewhere). Frozen expected files compared across platforms or across these deliveries need a line-ending and formatting decision first. | [`ProcessTests.fs`](../tests/Morphir.CodeGeneration.FSharp.Extension.Tests/ProcessTests.fs), [F# generation](../docs/content/docs/backends/fsharp/_index.md) |
| IR v4 kit canonical spellings | Two canonical JSON statements in the pinned IR v4 kit disagree with other statements in the same kit, and the reader gives each pair one model. `definitions-0020` writes an annotation with no arguments as `{ "name": … }`, while `definitions-0021` and `definitions-0022` write the same kind of annotation as a compact string. `distributions-0004` spells the module path as `u-s/f-r-2052-a/data-tables`, while `names-0001` and `names-0008` keep the same kind of name as `US` and `FR-2052-a`. The .NET writer uses the compact annotation string and the `CanonicalNames` spelling. Its tests keep both cases listed, and they fail if the kit is corrected. | [`V4JsonWriterTests.fs`](../tests/Morphir.Models.Tests/Json/V4/V4JsonWriterTests.fs), [pinned kit](../tests/Fixtures/MorphirIon/kit/) |
| MEP lifecycle before initialization | The pinned contract allows only `describe` and `initialize` before `initialize`. The Rust and MoonBit guests also accept `morphir.ping`. `Morphir.Mep` follows the contract and answers `-32014`. The `-32014` and `-32013` messages differ between the upstream peers; `Morphir.Mep` uses the transcript texts. A second `initialize` gets `-32600` "Extension is already initialized", as both upstream guests answer; the contract does not name the code. | [`Session.fs`](../src/Morphir.Mep/Session.fs), [`SessionTests.fs`](../tests/Morphir.Mep.Tests/SessionTests.fs) |
| MEP request ids and cancellation | The MoonBit guest refuses string request ids with `-32600`. `Morphir.Mep` accepts u64 and string ids, as the contract says. No upstream peer sends or handles `$/cancelRequest`; the `-32800` behavior follows the protocol draft, with no reference partner. | [`Rpc.fs`](../src/Morphir.Mep/Rpc.fs), [`ConnectionTests.fs`](../tests/Morphir.Mep.Tests/ConnectionTests.fs) |
| MEP legacy transcripts | `lifecycle-violations.md` and `protocol-errors.md` initialize with `0.1`, which `Morphir.Mep` does not speak. Their replays use `0.2.0-draft.1`. Entries 5 and 6 of `protocol-errors.md` need the compile request type of `add-fsharp-compile` and are not replayed in the core. | [`SessionTests.fs`](../tests/Morphir.Mep.Tests/SessionTests.fs) |
| Call value codecs | morphir-elm writes test values with `DataCodec`, which no Morphir specification defines. Value codec 1 keeps its shape, so `morphir-tests.json` test cases can become call steps without a change to the values. Codec 1 does not copy four decoding defects: any value that does not decode is `Nothing`, a bad `Decimal` is `0`, a `Char` is the first character of any string, and `Unit` has no encoding. Value codec 2 is the kit's own encoding and the default. | [Value codecs](steps/steps-1.md#value-codecs), [`DataCodec.elm`](https://github.com/finos/morphir-elm/blob/main/src/Morphir/IR/Type/DataCodec.elm) |
| F# guest signature files | The F# guest claims the language `fsharp` with the file extension `.fs` only. A case that has a `.fsi` document therefore does not reach the guest: the host selects no language and refuses the compile with `compile.language_required` before dispatch. The in-process frontend refuses the same case with `fsharp.unsupported_signature_file`. The suite case `frontend-fsharp-0081` gives this difference; all other cases give the same IR and diagnostics through the guest. | [task 9.4](../openspec/changes/archive/2026-11-09-add-fsharp-compile/tasks.md), [`CliAdapterTests.fs`](../tests/Morphir.Frontend.FSharp.Tests/CliAdapterTests.fs) |

Upstream issue links and qualification reports are added when those follow-ups
run. This seed does not claim an upstream guest-kit qualification or a released
kit supersession.
